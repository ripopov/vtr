Viewer design / Proposal

Reload a running simulation

Launch Verilator or Icarus, open its waveform while it runs, then press Ctrl+R in native Volna, Alt+R in the web viewer, or click Reload in the title bar to see newly published samples without rebuilding the workspace.

This is an implementation plan. None of its stages has landed. It covers growing VTR, FST and plain VCD files, restarting a simulation at the same path, native Volna and the VS Code remote host. Browser sources need a retained file handle or a host that can fetch fresh bytes.

→The format is only part of the feature
VTR already exposes complete append-only sections before close. Its current mapped reader cannot safely watch a changing file. Volna rejects unfinished FST sections and does not open VCD directly. The pinned Verilator FST producer also withholds essential metadata until close.

User-visible contract

  1. Add a Reload icon button next to Open in the title bar, outside the window drag region. Accessible name: “Reload waveforms”; its tooltip shows the current host’s configured binding. Add the same action to the command palette and trace-chip context menu.
  2. The Reload shortcut refreshes all reloadable traces in the workspace. The title-bar button does the same. A chip’s Reload refreshes only that trace. Native Volna uses Ctrl+R, including on macOS; optionally provide Cmd+R as an additional native binding. Standalone WASM uses Alt+R (Option+R on macOS) only while the viewer has focus outside text inputs. Leave Ctrl+R, Cmd+R, Ctrl+Shift+R and F5 to the browser. In VS Code, contribute a “Volna: Reload waveforms” command with Alt+R scoped to the focused Volna editor; do not capture the shortcut globally or override unrelated editor bindings. All hosts dispatch the same core command. Expose the bindings through settings and display the effective shortcut in the tooltip.
  3. Keep trace letters, user names, placement, row order, nested groups, colors, translators, analog/stack modes, panel layout, markers and cursor. Keep the viewport’s absolute time interval; extend the available recording range and scroll bounds. Do not fit or follow the new end automatically. The existing fit/navigation actions reveal the new tail. Initial opening still fits the first readable snapshot.
  4. Read in the background while the old snapshot stays usable. Show pending status, then the loaded end time and one of “Reloaded”, “No new published samples”, or an actionable error. “No trailer” alone never proves the simulator is running or crashed; call it an incomplete snapshot.
  5. Coalesce repeated requests to one pending follow-up per trace. Closing a trace or opening another document cancels its refresh. A failed or over-budget candidate leaves the old snapshot intact. With several traces, report each result; each trace commits atomically and independently.
  6. Support an initial file that has metadata but no samples. If its header/hierarchy is not yet published, retain the source in a waiting slot with Reload enabled; the host’s Reload shortcut retries it without another file dialog. Never silently install default timescale metadata from a header-only VTR.
  7. After a rerun, resolve signals by hierarchy path components and duplicate ordinal, with shape/type compatibility checks. Keep missing or changed signals as unresolved rows with their saved presentation and a clear reason. Never bind an old numeric handle to a different signal. New hierarchy nodes become browsable.

Reload reads the trace; it does not restart, pause or send commands to the simulator. Samples still in the simulator’s buffers remain unavailable. Document periodic producer flushes and distinguish “nothing newly published” from a read failure.

VTR: no new waveform encoding is needed

SPEC §2.3–2.4 already defines recovery and append-only ordering. Container scanning stops at the first incomplete or CRC-failing section. Recovery tests verify exact prefixes, cuts inside payloads, zero-filled tails and visibility before the writer closes. They establish prefix readability, not safe concurrent mmap access or background flush acknowledgement.

The writer emits sections only after blocks finish; compression chunks are not independently readable signal sections. Block fullness is measured in records. A small or quiet run can therefore expose no new wave data for a long time. The interval checks occur only every 256 calls of set_time, log and end_tx; the configured interval is not a strict wall-clock deadline, and a paused producer does not publish by itself. A guarded Verilator trace opts into ten seconds, but ordinary tracing does not.

Add one acknowledged publication operation in the owning writer API, projected one-to-one into the C ABI. Prefer making flush() mean “all pending publishable sections are visible when it returns”, using an encoder barrier that also drains log encoders. Document the blocking cost. It does not require fsync and does not write the closing directory/trailer. Route Verilator’s flush hook through it. Publish metadata after declaration, and offer a separate live publication setting rather than requiring the crash guard.

At publication, advance a signal block’s existing time table through the last fully recorded time step even when no values changed. Do not invent value transitions. The current flush condition can skip a time-only block; change it and test quiet horizons, initial all-X/zero values and equal timestamps at block boundaries. Simulator publication must occur after the whole time step, not between its value emissions. This uses the existing block encoding; SPEC wording and writer/reader tests must describe the new guarantee.

No container version bump is required for basic waveform reload. If implementation introduces a new section or changes an encoding for live interval updates, that becomes a format change requiring SPEC, version policy, rationale, reader support, round-trip tests and regenerated fixtures together.

FST and VCD: published prefixes, not arbitrary EOF

For FST, scan framing with checked lengths before calling the decoder. Stop before an unfinished SKIP placeholder or incomplete final block; reject invalid interior blocks. Copy finalized blocks and declarations into a privately owned snapshot. Use embedded hierarchy when available, otherwise capture <trace>.hier and use fst-reader 0.17’s incomplete reader to reconstruct geometry. Derive the sample range from retained blocks rather than assuming an unclosed header has its final range. The existing zero-time-offset and dump-off limitations must remain explicit until implemented; the live path must not bypass them. A gzip wrapper being rewritten at close is retried as a whole, never treated as append-only compressed data.

The pinned backend is Verilator’s bundled fstcpp writer, also represented by the libfstwriter reference. Change the backend where it owns publication: emit a valid initial header and geometry/hierarchy after declarations are finalized, finalize each value section before exposing it, and make explicit flush work while paused. Test GTKWave/fst-reader interoperability and the completed file too. Reader heuristics cannot recover declarations that were never written.

For plain VCD, capture a fixed byte extent and require a complete $enddefinitions $end. Admit whitespace-terminated complete tokens and complete directive bodies; defer the unfinished terminal token/directive for the next reload. Preserve aliases, real values, vectors, X/Z and repeated changes at one timestamp. An EOF after a timestamp does not prove the entire timestep is finished: show the loaded data as a snapshot that can gain further changes at that time. Interior syntax errors fail explicitly. Evaluate wellen’s separate header/body APIs using partial-tail fixtures; wrap it only if these semantics hold, otherwise add bounded incremental tokenization at the trace adapter layer. Do not run a full external conversion or create a user-visible VTR file on every keypress.

Immutable snapshots through the session seam

Keep Session immutable. A refresh produces a new session and complete selected histories through the same local/remote contract. UI widgets dispatch commands and execute queued work; they own neither decoding nor binding rules.

  1. Retain a reload source. Model source capability separately from the display name: native path, remote URI/reader launch specification, retained browser FileSystem handle, or host fetch callback. A one-shot byte upload cannot read new disk data; disable Reload with a reason. An HTTP host must bypass stale caches and validate the new response. Do not retain a second full byte image solely as a reload descriptor.
  2. Request and capture. Add shared ReloadAll/ReloadTrace(TraceId) commands and generation/request-tagged refresh work. The owning library captures a fixed readable extent into immutable storage; adapters supply paths/handles, not format-specific copying logic. For native large files, stream into a bounded temporary snapshot file and map that private file; browser byte images use owned buffers. Count RAM and temporary disk limits explicitly, clean up on cancellation/error, and retain private storage as long as any immutable result owns it.
  3. Validate a publication boundary. Permit source growth past the captured extent. For append-only VTR, validate complete sections and retain the verified prefix, allowing an incomplete new tail. Detect replacement/truncation and retry a fresh capture. For FST, header fields and section finalization can be rewritten: recheck relevant framing/header bytes and the hierarchy pairing, decode selected data before accepting, and discard inconsistent captures. Metadata stamps are hints, not a transactional snapshot guarantee. Use bounded retries (three attempts, a two-second acquisition deadline); retain the old view if publication keeps racing. Producer publication tests are essential because a reader alone cannot guarantee consistency for arbitrary concurrent rewrites.
  4. Prepare against the current workspace. Collect all referenced signal paths, clocks, tracks, table/pipeline sources and pinned details, including folded/hidden panels. Resolve against candidate metadata and load the complete currently retained histories/tracks within the shared memory/object budget. Deduplicate aliases. Charge old plus candidate owners until commit; reject an over-budget refresh without destroying the current view. Reconcile edits made during acquisition before commit, or discard/reprepare if its workspace revision changed.
  5. Commit one trace. Keep its TraceId, name and placement; swap the session, bump its generation and invalidate every result derived from that trace: values, edge lists, summaries, integral/stack/analog caches, scope sizes, activity answers, clock rulers, transactions, tables, pipeline maps and hover/selection records. Reject stale signal, track, hierarchy-page, index-build and remote-transfer results. Rebind missing rows without deleting them. Resolve a pinned transaction only within a proven same recording; after rerun keep its query intent but clear the stale record ID and explain it.
  6. Keep navigation and history coherent. Store navigation in absolute session time. Handle a changed timescale through existing exact unit refinement, including marker/viewport/history rescaling and overflow rejection. Reload is a data refresh and creates no undo step. Rebind stored row edits and trace-close inverses in the journal too: Undo/Redo must use the newest session for that TraceId, never resurrect old samples or reused signal IDs. Explicit row removal, rename, add/close and layout edits remain journaled through their existing single writers. Exercise this in the history model test.
  7. Remote replacement. Capture an immutable snapshot beside the source and open a new reader session with a fresh server identity on each reload, using the existing raw metadata/history protocol. Keep the old remote session alive until the candidate is accepted. Check the private snapshot’s identity rather than rejecting ordinary growth of the source. Propagate waiting/error/capability through the host seam; stop obsolete readers and transfers after commit/cancellation. Protocol changes, if needed for diagnostics, are versioned; presentation remains client-side.

Never reuse <trace>.index merely because its path is unchanged. Validate it against the new snapshot identity; a growing recording invalidates the old whole-recording activity index. Cancel builds for the replaced generation, prevent them installing stale results or overwriting a new sidecar, and keep live snapshots unindexed unless the index explicitly describes that immutable snapshot. No automatic repeated index build on each refresh.

Initial live opening uses the same capture path as refresh. Completed path-based sessions that can later be overwritten also need safe ownership; merely switching to snapshots after the first refresh leaves the initial mmap vulnerable to a rerun. Keep the existing static Reader::open contract for callers that guarantee immutability, and add snapshot acquisition at the VTR library’s owning layer.

Borrowed and rejected approaches

GTKWave’s Reload Waveform establishes the file-refresh interaction, including its source capability restriction. Surfer’s reload and switch_file establish retaining the waveform view. Borrow those interactions, while expressing refresh as a core command over Volna’s several traces.

Chrome’s shortcut reference reserves Ctrl+R/F5 for page reload and Ctrl+Shift+R for cache-bypassing reload. Use a separate configurable viewer binding in WASM. VS Code’s keybinding contributions support context conditions: scope the Volna command to its focused editor instead of intercepting host keys in every webview.

GTKWave/libfst’s implementation uses deferred flush requests and finalized value sections; it also supports hierarchy outside the main file. Icarus’s FST dumper routes $dumpflush to that deferred request. Its VCD dumper flushes its file buffer. Test after subsequent simulation progress for FST; a flush call alone is not evidence that new samples are already readable. Verilator’s tracing guide describes FST/VCD generation; the checked-in backend determines this checkout’s publication behavior.

  • Rejected: close and reopen the document. It discards layout and row intent and cannot preserve edits safely.
  • Rejected: mutate mapped input or resident histories in place. Old objects outlive sessions; a source truncate can invalidate mappings. New generations must own immutable data.
  • Rejected: pretend every FST supports live opening. Some producers withhold declarations; fix our pinned producer and report unsupported external publication explicitly.
  • Rejected: accept all parser errors as a growing tail. Only incomplete terminal framing is recoverable; invalid interior data must remain visible as an error.
  • Deferred: automatic polling, follow-tail and incremental delta transfer. Manual refresh is the requested behavior. First deliver complete immutable snapshot replacement; measure full capture costs before adding an owning-layer incremental snapshot API. These optimizations are not prerequisites for correct Ctrl+R.

Implementation stages

Stage 1 — Capture and diagnostics

Add library-owned immutable VTR snapshot acquisition, typed prefix diagnostics and host source capabilities. Use it for initial reloadable opens as well as refresh. Share native/remote capture code. Verify active writes, a partial section, restart/truncate, cancellation, limits and old-result lifetime. Update VTR rustdoc/C header where the public API changes and record decisions in RATIONALE.

Stage 2 — VTR publication

Add the encoder/log drain barrier, early metadata, opt-in simulator publication and quiet-time advancement. Publish blackout snapshots; fix log-only ranges and declare the limits of open transactions/clocks. Route the Verilator flush API through the new semantics. Keep ordinary throughput defaults; do not depend on the crash guard. Update SPEC, rationale and round-trip fixtures/tests for any changed semantics.

Stage 3 — Live FST, including the pinned producer

Implement finalized-prefix capture and the incomplete reader with a captured .hier companion. Fix the bundled Verilator FST writer’s metadata and flush lifecycle. Keep tooling/tests in integrations/verilator; backend code belongs in the pinned submodule because this gap is in the producer. Verify both upstream libfst/Icarus and this checkout’s fstcpp output before calling FST live-ready.

Stage 4 — Direct VCD sessions

Add toolkit-neutral VCD loading, partial-tail semantics and the same immutable selected-history API. Reuse wellen only after fixture verification. Update source sniffing, file filters, server usage, browser/VS Code associations and guides. Support VCD directly throughout this feature; conversion is not its user workflow.

Stage 5 — Core refresh and journal rebinding

Add request coalescing, candidate preparation, per-trace atomic replacement and all cache invalidations. Preserve navigation and workspace edits; rebind both current state and journal inverses by durable paths. Extend volna-core/tests/history.rs with reload/restart interleavings and tests/traces.rs with multi-trace failure isolation and timescale changes.

Stage 6 — Title bar, keyboard and remote hosts

Wire the shared command to GPUI title-bar chrome, native Ctrl+R, WASM Alt+R, the focused VS Code editor binding, palette and chip menus. Add accessible waiting/loading/error states and host-specific shortcut tooltips. Extend native loader, VS Code server lifecycle and WASM source capabilities; test focus-scoped dispatch and preservation of browser reload keys. Preserve the minimal egui frontend’s build and behavior without adding feature parity.

Stage 7 — Simulator acceptance and cost measurements

Run the live-writer matrix below and measure capture, decode, commit and peak memory/disk across small traces and openC910. Compare full reload against current ordinary open and measure publication size/write/read costs against HEAD in the same session. Any writer/decode-path change requires the full benchmark suite before results are updated. Publish measurements together; do not claim instant reload or bounded live latency without measured evidence. Mark stages Landed only when their code, documentation and automated gates exist.

Headless acceptance gates

Add a checked-in runner under integrations/verilator/reload/ that provisions a small traced design, starts a real producer, controls checkpoints through pipes, owns temporary files and enforces deadlines. It must observe the producer still running at both reads. Generate FST and VCD with Icarus and Verilator, and VTR with the pinned Verilator backend. CI installs/pins every prerequisite; a missing simulator is a failure, never a skipped pass. Avoid wall-clock sleeps as the synchronization contract.
