One tree for signals, streams and logs in Volna's sidebar

A VTR file is one hierarchy: RTL scopes and variables next to transaction streams, their generators and log sites. Volna's sidebar currently shows only the first half. This proposal shows the whole tree, gives every node kind an icon that says what it is, and keeps one rule for what Enter does. No new settings, no new panels.

existing already in the repository, reused as is proposed the change described here library offered by gpui-kit 0.6.1, considered

Prerequisite for pipeline-view.html, whose panel opens from this tree. Companion to workspaces.html (sidebar state in the workspace file). Status: proposal, nothing implemented yet.

Recommendation

Five decisions

1 · Containers in the tree, members in the list

The upper pane lists what contains things: scopes and streams. The lower pane lists what a container holds: variables of a scope, generators of a stream, log sites of a LOG stream. The two-pane layout stays; what changes is that streams are containers and generators are members. Enum tables never become rows: they are type information for a variable.

2 · Icons say what a node is; tags say what we do not recognize

Every scope type, stream kind and member kind maps to a Lucide icon through three small functions in the core. Recognized stream kinds (PIPELINE, LOG) get their own icon and colour; any other kind gets the generic transaction-stream icon plus a small tag with the kind string, so an FTR TRANSACTOR or an OpenTelemetry otel.scope is still identifiable.

3 · One action per member kind

Enter and double-click mean "put it in the main area": a variable is added to the focused wave panel (today's behaviour), a generator or a stream opens as a pipeline panel (Command::OpenPipeline). A log site is listed but has no action until a log panel exists; the status line says so.

4 · The model stays in the core

Hierarchy gains a role on scopes and a generator table; ScopeTreeModel flattens streams like scopes; VariableListModel becomes a MemberListModel over an enum of members. Frontends keep painting uniform_list rows from the flattened model; the keyboard, filter, reveal and persistence code is unchanged in shape.

5 · Search covers every member

The whole-trace search that the filter box already offers for variables returns generators and streams too, each with its icon and full path, so "find the write generator" and "find the rdata signal" are the same gesture.

What this does not add

No inline-variables tree style, no sorting, no counts on tree rows, no context menus, no drag and drop, no log panel, no settings. Each is listed under Later with the seam it would use.

What the mock implements versus what is proposed. The tree flattening, keyboard model, filter and multi-selection follow ScopeTreeModel and VariableListModel line by line, extended as this document proposes; the icon mapping is the proposed one, rendered from the same Lucide SVGs gpui-kit ships. The main area is a placeholder for the wave and pipeline panels. Tooltips are plain title attributes. There is no workspace file, no unresolved-path state and no reveal-on-restore.

Icon catalogue

Every node kind, one glyph

All icons are Lucide, already bundled by gpui-kit-assets 0.6.1 and copied into volna-core/assets/icons like the existing ones. The choice favours silhouettes that stay distinct at 14 px in both appearances; colour is used only where a kind needs to stand out at a glance (stream kinds, port direction), and the same tokens serve light and dark themes.

Architecture

Why generators are members and not tree nodes

A stream is to its generators what a scope is to its variables: a declaration container whose children are the things you actually put on screen. An OpenTelemetry scope stream can declare hundreds of span-name generators and an FTR transactor a few dozen; a pipeline stream declares one. Listing them in the member pane keeps the tree shallow, gives the filter box something to filter, and means "select container, then act on members" is the one gesture for both halves of the file. The earlier draft in pipeline-view.html placed generators in the tree; it now follows this rule.

Core API

Sketch

// data/source.rs
pub enum ScopeRole { Scope, Stream { kind: String, track: TrackRef } }
pub struct Scope { pub name, pub kind: String, pub role: ScopeRole, pub parent, pub children, pub vars: Vec<VarId>, pub generators: Vec<GeneratorId> }
pub struct Generator { pub name: String, pub stream: ScopeId, pub track: TrackRef, pub log_site: Option<LogSite> }
pub struct LogSite { pub severity: Severity, pub file: Option<String>, pub line: Option<u32> }   // from the `log.*` node attributes
pub struct Variable { .., pub enum_table: Option<EnumTableId> }
impl Hierarchy { pub fn find_generator(&self, path: &[impl AsRef<str>]) -> Lookup<GeneratorId>; pub fn generator_path(&self, id) -> Vec<String>; }

// sidebar/members.rs (was variables.rs)
#[derive(Clone, Copy, PartialEq, Eq)]
pub enum Member { Var(VarId), Generator(GeneratorId), Stream(ScopeId) }
pub struct MemberListModel { pub scope: Option<ScopeId>, pub filter: String, pub everywhere: bool, pub rows: Vec<Member>, pub selected: BTreeSet<usize>, pub anchor: Option<usize> }
pub struct MemberKeyOutcome { pub changed: bool, pub activate: Vec<Member>, pub reveal: Option<usize>, pub focus_filter: bool }
impl MemberListModel {
    pub fn title(&self, h: &Hierarchy) -> &'static str;          // "Variables" | "Generators" | "Log sites" | "Results"
    pub fn breadcrumb(&self, h: &Hierarchy) -> String;
    pub fn placeholder(&self, h: Option<&Hierarchy>, loaded: bool) -> Option<&'static str>;
    pub fn describe(&self, h: &Hierarchy, m: Member) -> String;   // tooltip text
}

// sidebar/icons.rs
pub enum Tint { None, Pipeline, Log, Stream, In, Out, InOut }    // resolved to theme tokens by the frontend
pub fn scope_icon(scope: &Scope) -> (IconName, Tint);
pub fn member_icon(h: &Hierarchy, m: Member) -> IconName;
pub fn direction_icon(d: Direction) -> Option<(IconName, Tint)>;
pub fn stream_tag(scope: &Scope) -> Option<&str>;               // the kind string for unrecognized stream kinds

// app.rs — the member activation replaces the variable-only path
Command::ActivateMembers(Vec<Member>)   // vars → AddVars, generators/streams → OpenPipeline, log sites → Notice
Command::SetSearchEverywhere(bool)

// icons.rs — new variants, SVGs copied from gpui-kit-assets
IconName::{Boxes, Cpu, Component, Cable, Package, SquareFunction, GitFork, Brackets, Zap, Layers, Terminal, Server, Library,
           Workflow, ScrollText, ChartNoAxesGantt, Hash, Pi, Tags, CircleDot, MessageSquare, LogIn, LogOut, ArrowLeftRight}

Theme: three tint tokens (sidebar_pipeline, sidebar_log, sidebar_stream) and three direction tokens, derived from existing accent colours in Theme::one_dark() and from the host palette with the usual 3:1 contrast floor. Persistence: selected and expanded paths already cover streams because they are scopes; the search-everywhere flag is transient and not saved.

Interaction

Keys, pointer and states

Scopes pane existing + streams

↑ ↓ move the selection; the member pane follows → expand ← collapse, or go to the parent; a childless row goes to the parent at once (today an expanded leaf swallows the first press, since reset marks second-level rows expanded whether or not they have children) ⏎ Space toggle a container with children; open a childless stream as a pipeline Tab move focus to the member pane

Click selects, double-click toggles or opens, the chevron toggles without selecting. Expand all / collapse all in the header as today.

Members pane existing + generators

↑ ↓ move; ⇧ extends the selection ⏎ activate the selected members, or add all listed variables Esc clear the selection, then the filter typing focuses the filter box and filters the listed members Search everywhere the filter searches the whole trace: variables, generators, streams, shown with full paths

States the panes must show

  • No trace: "Open a trace to browse variables" as today.
  • Container without members: a scope with only child scopes says so; a stream without generators says "This stream declares no generators".
  • LOG stream selected: title "Log sites", rows with severity badge and file:line; Enter does nothing and the status line explains.
  • Search with no hits: "No members match"; the 5 000-row cap is kept and a trailing row says when it was hit.
  • Unresolved saved selection: retained and written back as today; streams included.
Frontends

Row painting, nothing structural

GPUI

  • Tree rows add the tint from scope_icon and the kind tag; member rows swap the direction text for the icon and add the severity badge. The uniform_list structure, focus handles, scroll tracking and reveal events are untouched.
  • The member pane header reads its title and count from the model; a one-line breadcrumb under the header shows the selected path and kind (mono, muted, ellipsis).
  • A "Search everywhere" toggle sits beside the filter box; it maps to SetSearchEverywhere.
  • Icons: the listed Lucide SVGs are copied into volna-core/assets/icons; nothing is fetched at run time.

egui and VS Code

  • The egui frontend keeps calling the same icon functions; new variants get a stroked drawing in paint.rs like the existing ones. Its list draws generator rows without an action, which preserves its current feature set as AGENTS.md requires.
  • VS Code hosts the GPUI web build; the host palette supplies the tint tokens through the existing snapshot path.

Alternatives considered

Rejected, and why

gpui-kit's Tree component

It owns expansion, selection and reveal in its TreeState, which would duplicate what ScopeTreeModel already decides and put viewer state in a frontend. It also builds an item tree eagerly; the core's flattened rows scale to large hierarchies with uniform_list as today. Keep the library for chrome that has no core model.

Generators as tree nodes

Reasonable for one-generator pipeline streams, poor for transactor and OpenTelemetry streams with dozens or hundreds. Members in the list keep the tree shallow and reuse the filter and multi-selection.

A separate "Streams" panel

Hides the fact that streams live inside the design hierarchy and would need its own selection, filter and persistence. One tree, one set of rules.

Hiding unrecognized stream kinds

The file's content should be visible whatever produced it; a generic icon plus the kind tag costs nothing and helps when a new producer appears.

Coloured icons for every scope type

Colour that carries no decision is noise. Tints are reserved for the three stream families and the port directions, where they answer a question the user actually has.

Direction as text, as today

Text works but competes with the name column; three small tinted glyphs read faster and free width for long names. The tooltip keeps the words.

Plan and verification

Four steps

  1. Model. ScopeRole, Generator, Member, MemberListModel, icon functions, build_hierarchy extension, find_generator. Existing headless tests pass; new ones cover a VTR fixture with streams, generators and a log stream.
  2. Commands. ActivateMembers, SetSearchEverywhere; AddVars stays for hosts that call it directly; OpenPipeline lands with pipeline-view.html, until then generators activate to a notice.
  3. Frontends. Icon assets, GPUI rows, breadcrumb, tags, badges, direction icons, search toggle; egui stroked icons; a viewer screenshot of the mixed tree.
  4. Documentation. ARCHITECTURE.md sidebar section, VERIFICATION.md checks, AGENTS.md row.

Headless checks that define done

  • Opening the Kanata demo trace lists cpu › thread0 as a stream row with the pipeline icon and tint; selecting it lists one generator with the generator icon; the title reads "Generators".
  • A stream of an unrecognized kind gets the generic icon and its kind as a tag; a LOG stream lists log sites with severity and location and its title reads "Log sites".
  • Search everywhere for a name that matches a variable, a generator and a stream returns all three with full paths, in that order, under the row cap.
  • Enter on a selected variable produces AddVars; on a generator produces OpenPipeline with its TrackRef; on a log site produces a Notice and no load request.
  • Saved selection and expansion of a stream path restore; an unknown stream path stays unresolved and is written back unchanged.
  • Every scope type name and stream kind in the catalogue maps to an icon variant that has an SVG asset; the test enumerates them.
