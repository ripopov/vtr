Retain useful coverage

A pan may keep prior data from the same dataset. A new snapshot, signal set or raw filter clears that slot’s retained handle. Formatting alone does not invalidate raw data.

Cancel at the worker

Discard obsolete queued work. Stop running work between bounded decoder units when it serves no subscriber. Dropping a future alone does not stop CPU work.

Recover by identity

Retry an incomplete page while the snapshot survives. After document-session loss or child restart, reopen and resolve saved paths. A matching file name or design ID is not proof of the same trace.

04 / A small vocabulary of raw questions

Every reply says whether it is complete, partial or failed. A continuation is a position in an immutable snapshot, not a growing server-side result set.

The VS Code wire is compact binary Protobuf over length-prefixed child stdio frames, relayed through webview messages. These readable examples explain the logical contract; they are not a frozen schema. Native local calls return the same logical data without encoding.

Proposed starting limits, not measured optimal values. Validate byte counts, nested fields, references and allocations before accepting work. A record too large for a page uses paged parts or a typed value reference.


What makes exact results safe to interpret?
Use integer timestamps and IDs end to end. Preserve packed 2/4/9-state logic, real bits and variable-length bytes. Half-open windows include the start and exclude the end. Same-time events preserve source order across page boundaries. AfterMax represents the exclusive bound beyond u64::MAX. Partial coverage never means “no events.”


Why bounded pages over stdio?
Each query returns one bounded page; continuation is requested only when needed. Request IDs permit concurrent replies. The extension bounds both queues, pauses stdout reads under backpressure, and reserves capacity for cancel and close. Control cannot preempt a frame already being written, so frame size and cancellation delay are measured.


How does VS Code reach the native server?
The workspace extension launches one native child per trace document on the workspace host. It relays opaque binary envelopes between the WASM webview and child stdin/stdout. VS Code carries the remote connection. No HTTP endpoint, port forwarding, service token or network CSP change is needed. Document disposal closes the child; temporary disconnection retains data only after the same child incarnation is confirmed.



05 / Cache data where it belongs
Two memory budgets.
One clear boundary.
The client caches answers. The file host caches the work needed to answer. Both count bytes, including pinned data and temporary buffers; neither grows a permanent cache of every selected history.

Decoded data, scratch and output. Resident metadata/indexes are charged separately against a process ceiling.


Does a small summary always mean a cheap query?
No. Without a suitable index, a full-range summary may scan many events while returning only a few bins. Use reusable signal indexes as the primary warm-query path in both deployments. Measure build cost and memory; use bounded scans for histories that do not fit, and add coarser aggregates if that fallback misses latency gates. Disk backing or a versioned sidecar needs measured justification; small replies alone do not prove bounded server CPU.


Where do future source, schematic and pipeline views fit?
The client attaches VDB by exact build identity, chooses visible symbols or nets, and batches raw value queries. A driver investigation evaluates VDB expressions on the client and requests exact samples or previous/next edges. Pipeline views request raw transaction windows, events, stages and relations; the client assigns lanes and styles. Source/VDB file retrieval is a separate artifact boundary. MCP adapters reuse core commands and raw queries.


What is deliberately absent from the trace protocol?
No rendered pixels, Scene lists, colors, visual row positions, source/design mappings, VDB expressions or user annotations. No automatic bulk-transfer mode, arbitrary SQL RPC, mutable live trace subscription, or per-client full-history store. Version one serves immutable recordings; new recordings create new snapshots.





06 / Prove each layer before claiming the whole
Build from the reader
out to the remote view.
The design is proposed, not shipped remote support. Correct results, bounded resources and responsive frames are separate gates—and all three matter.


Establish native performance & relay behavior
Dense and sparse waveforms, wide values, large hierarchies, long overlaps and relation fanout. Compare local, loopback and shaped network paths, including the native workspace-host VS Code deployment matrix. Measure native cold/warm latency against the existing viewer; local calls share buffers without encoding.
Make local queries bounded
Exact pages match reference histories. Ordered reductions match direct summaries. Same-time events, extreme timestamps, huge records, byte limits and cancellation all have explicit tests.
Move the core to demand slots
Use a delayed, reordered, failing fake session. Keep only the latest pending intent, share answers across panels and prove that a long navigation session reaches a memory plateau.
Add the server & host adapters
Run the same conformance corpus in process, over stdio and through the VS Code relay. Test interrupted bodies, document disposal, server restarts, parser limits and slow clients.
Extend to transactions & investigations
Validate long overlaps, point events, detail pagination and cross-window relations. Exercise source sampling and driver stepping without moving VDB interpretation to the server.


Responsive frames.
Trustworthy evidence.
Proposed targets include p95 frame work below 16.7 ms for 32 rows, and warm visible queries below 200 ms at 50 ms RTT / 100 Mbit/s. These are validation gates, not demonstrated results. The research document defines the conditions and remaining experiments.
