Dockable waveform panels and persistent workspaces for Volna

Several waveform panels over one trace, arranged in VS Code-style splits and tabs, with linked or independent viewports and cursors, and a workspace file that brings the whole debugging session back when the trace is reopened, natively or inside VS Code.

existing already in the repository implemented workspace implementation library provided by gpui-kit 0.6.1

Implemented in the toolkit-free core, native GPUI viewer and VS Code host. This document records the format, ownership and operating rules. See VERIFICATION.md for reproducible checks and performance measurements.

Recommendation

The simplest coherent design

Panels live in the core

implemented volna-core owns a Panels model: a toolkit-neutral layout tree of splits and tab groups, a map of panels keyed by a stable PanelId, and a focused panel. Each waveform panel owns a WaveModel (rows, viewport, cursor, selection). The Document keeps what every panel shares: the session, markers, translators and load bookkeeping. Keyboard actions go to the focused panel; pointer events name their panel.

Two link flags per panel, no groups

implemented Synchronisation is two toggles per panel, follow viewport and follow cursor, shown as icon buttons in the panel header. A linked panel reads the one shared viewport and cursor stored on the document; an unlinked panel keeps its own. Nothing is copied between panels, so linked panels cannot disagree. With a single panel the header is hidden and the same toggles sit in the View menu and status bar, where they are also reachable by keyboard.

Reuse gpui-kit's dock engine

library The GPUI frontend hosts the central area in gpui-kit's DockArea, which already provides nested splits, tab groups, drag-to-reorder, drag-to-split, zoom and a serde round trip. implemented A thin adapter mirrors the core layout into the dock and translates dock edits back; a wrapper renderer hides the tab bar when the centre holds one panel, so today's viewer looks unchanged.

One workspace format, thin hosts

implemented volna-core::workspace defines a versioned JSON document, captures it from App, restores it in two steps (prepare and validate without touching live state, then commit), and schedules autosaves. Hosts only move bytes and never parse them: the native app writes trace.vtr.volna.json beside the trace, the VS Code extension writes the same file through workspace.fs so remote files work, and both fall back to per-user storage when the trace directory is read-only.

What stays out. Nothing presentational enters VTR, VDB or the future raw-data query protocol; workspace files are a client-side annotation beside the trace. The egui frontend keeps rendering exactly one panel, the focused one, and gains no persistence. No new panel kinds ship in this scope, but the panel model, workspace format and dock registry are keyed by kind so transaction, source and pipeline panels slot in later.

Facts from the VS Code extension guides that shape the host adapter:

  • Webview state. getState/setState "is persisted even after the webview content itself is destroyed when a webview panel becomes hidden", but "the state is destroyed when the webview panel is destroyed". They are "the preferred way to persist state, as they have much lower performance overhead than retainContextWhenHidden", which "has high memory overhead and should only be used when other persistence techniques will not work". (Webview guide, Persistence.)
  • Restart. A WebviewPanelSerializer restores plain webview panels across restarts. Custom editors are editor inputs: VS Code reopens them with the workspace and asks the provider to openCustomDocument and resolveCustomEditor again, so restoring a Volna editor is the same code path as the first open. The custom editor guide recommends workspace.fs for writing files, which also covers remote and virtual workspaces.
  • Multiple editors. "By default, VS Code only allows there to be one editor for each custom document"; Volna currently opts into supportsMultipleEditorsPerDocument: true. With internal panels covering the split use case, two editors autosaving one sidecar would race, so the proposal turns this off.
  • Read-only provider. Volna's traces are never edited, so the provider remains the read-only shape: no backup, save or revert hooks. Workspace files are separate from the document and never mark the editor dirty.

Panel model and interactions

Core types implemented

pub struct PanelId(pub u64);
pub enum Axis { Horizontal, Vertical }

    Tabs { tabs: Vec<PanelId>, active: PanelId },
    Split { split: Axis, sizes: Vec<f32>, children: Vec<Layout> },
}
pub enum PanelKind {
    Waves(Box<WaveModel>),
    Unsupported(Box<serde_json::value::RawValue>),
}
pub struct Panel { pub id: PanelId, pub title: Option<String>, pub kind: PanelKind }
// WaveModel owns Link { viewport: bool, cursor: bool }.
// Panels owns layout, panel map, focused ID, next allocation ID and revision.
// New IDs are monotonic. Restoring saved IDs creates a new document generation.

Invariants the core enforces after every command: the layout references every panel exactly once, tab groups contain at least one panel, splits contain at least two children, sizes are normalised, and at least one waveform panel exists. Files are bounded to 16 MiB, 4,096 panels, layout depth 64 and 100,000 total rows. Closing the last waveform among unsupported panels empties its rows and preserves its view. Closing the final panel through the app flushes the workspace and closes the trace, leaving a fresh empty panel. The layout never has zero panels.

What moves, what stays

Shared on Document

  • existing session, translators, hierarchy access, load generations and pending set
  • existing markers, now with an id and optional label so chips are addressable and a workspace can name them (Marker{id, time, label})
  • implemented shared: Shared { viewport: Viewport, cursor: Option<u64> }, the values every linked panel reads. Always present, even while no panel is linked, so re-linking has a value to adopt.

Per panel on WaveModel

  • existing rows (DisplayedSignal), selection, viewport and animation, scroll, column widths, hover and drag state, format menu
  • implemented cursor: Option<u64> moves here from Document; the panel's own viewport and cursor are used only while the corresponding link is off
  • implemented RowSource::Unresolved{path, nth, ambiguous} retains the exact locator for a placeholder; resolved rows hold real variable and signal handles

Load fan-out changes from "the one model" to "every waveform panel that shows this signal": App::deliver iterates the panels, and histories stay shared Arcs across panels exactly as they are shared across duplicate rows today. A history is released when the last row in any panel drops it.

Synchronisation semantics implemented

  • Two flags per panel. link.viewport and link.cursor, both on by default. New panels inherit the flags of the panel they were split from.
  • Linked means "reads the document value". A panel's effective viewport is doc.shared.viewport when link.viewport is on and its own WaveModel::viewport otherwise; the same for the cursor. When a linked panel pans, zooms, fits, animates or sets the cursor, the core writes doc.shared once; every linked panel paints from it. There is one copy of each shared value and no reconciliation pass. Unlinked panels are untouched.
  • Toggling. Turning a flag off copies the shared value into the panel's own field, so the panel stays where it is and now moves alone. Turning it on discards the panel's own value and adopts the shared one, which is retained even after every panel has been independent.
  • Edge stepping and "centre on cursor" read and write the focused panel's effective cursor and viewport, so linked panels follow through the shared value.
  • Markers are always shared; M adds a marker at the focused panel's cursor.
  • One panel: the same rules apply. Re-linking can return it to a retained shared position; a later split inherits its flags.

This is deliberately weaker than named sync groups (as in Verdi or GTKWave "locked" windows): one global link per dimension covers the two common cases, "everything follows" and "this one is my independent zoomed-in view", and it needs no group management UI. Groups can be added later with a versioned format change if a workflow needs them.

Visual rules

  • Single panel in the centre: no header, no outline. The element tree, geometry and default chrome match today's viewer, so the Metal and egui screenshot baselines stay valid.
  • Two or more panels: each tab group shows a tab strip (VS Code-style: active tab in surface colour with an accent top edge; inactive tabs dimmed). The focused panel's tab and a 1 px accent outline around its body mark keyboard focus; unfocused panels draw their cursor line with the wave_cursor_inactive token at reduced contrast so the eye finds the active panel. All colours are theme tokens (theme::Theme), so VS Code themes and One Dark both resolve them.
  • Status bar shows the focused panel's name and its two link states as chips when more than one panel exists; the trace range, cursor time and resolution shown today refer to the focused panel.

Docking library

  
Integrating gpui-kit's DockArea

  
The engine fits: it already implements the tree editing, drag semantics and serialisation that would otherwise be several thousand lines, its appearance is replaceable, it has no native-only code, and Volna already links it. The integration keeps the core tree authoritative and treats the dock as a view of it, following Surfer's adapter pattern.

Hiding the header for one panel

  
PanelStyle::Auto still draws a 30 px title row. Volna installs VolnaDockRenderer, a DockAreaRenderer that forwards every hook to the stock DockSkin and wraps its tab_group_renderer(): when the centre tree has exactly one panel, render_tab_bar returns an empty element and frame drops the group border, so the panel body starts at the same y-offset as today's WaveTable. TabGroupSkin is crate-private but reachable through the trait, so this is composition, not a fork. Native and browser interaction checks exercise the header wrapper and returning from multiple panels to one. No second single-panel rendering path is needed.

  
Limitations to accept or work around

  
    
    
  • Closure uses one group toolbar button, the panel menu and ⌘W. Library-owned close is disabled: the core must enforce the last-waveform invariant and flush before closing a trace. This avoids a second deletion path inside the skin.
    • 
    
  • No next/previous tab action: the core implements FocusNext/FocusPrev over its own tree.
    • 
    
  • Sizes are pixels in the dock and written back only when a drag ends; fractions in the core, converted both ways. Only a user sash drag may change the fractions; a window resize reflows pixels and must not be read back as an edit.
    • 
    
  • Panel::on_removed also fires for every panel during a wholesale set_center, and a move between groups is not a removal. The adapter treats these callbacks as widget detachment only; only PanelsCommand::Close deletes a panel from the model.
    • 
    
  • Zoom is per container and not persisted; acceptable.
    • 
    
  • Single global minimum of 100 px; fine for waveform panels.
    • 
    
  • The same adapter runs in ordinary Chrome and the default VS Code webview, including without cross-origin isolation or SharedArrayBuffer.

Workspace data model

  
The workspace file

  
A JSON document owned by volna-core::workspace, written with serde_json, human-readable and diffable so colleagues can share and review it. Cursor, marker and trace-range timestamps are u64 integers in trace ticks. Viewport bounds retain the current finite f64 representation, including fractional ticks and negative edge space; require start < end. Signals are referenced by their hierarchy path as an array of segments, the same segments scope_path and the variable name produce today. A dot-joined string is deliberately not used: escaped HDL identifiers can contain dots, and the segment form needs no escaping contract.

  "sidebar": { "visible": true, "width": 280.0, "scopes_fraction": 0.42,
               "selected_scope": ["testbench", "top"], "expanded": [["testbench"], ["testbench", "top"]], "filter": "" }
}

  
FieldRule

    
format, versionBoth checked before anything else. A different format string or a newer major version rejects the file with a notice; older versions are not migrated during the research phase (GOAL.md §8). The file is left untouched.

    
traceIdentity of the trace the workspace was captured from. On restore the name and timescale are compared: a different timescale warns and restores times unchanged; a different name warns but proceeds, because renamed traces are common. design_id is compared when both sides have it.

    
layout, focusedThe same tree as Panels::layout; sizes are fractions; active and focused are panel ids (the core keeps an index). An invalid tree (unknown or duplicate id, empty group, an active that is not a member) fails prepare as a whole and reports why; nothing live changes.

    
supersedesFallback base: a lowercase SHA-256 hex string, or null for no base. Omitted for other workspace files. Core uses it for restore selection; hosts carry the JSON unchanged.

    
integersTimestamp and panel-id integers round-trip exactly through Rust JSON; hosts carry workspace JSON as opaque text. Save-ticket epoch/revision values cross JavaScript separately as decimal strings and are echoed unchanged. Viewport bounds are floating-point numbers, not exact timestamp identities. The playground uses small values only.

    
panels[].kind, versionPanels are decoded into PanelKind by name; an unknown kind or newer version is kept as raw JSON (serde_json::value::RawValue) in a placeholder panel that draws "unsupported panel" and is written back verbatim unless explicitly renamed (only the title changes), so a workspace saved by a newer Volna survives a round trip through an older one.

    
rows[].signalResolved by Hierarchy::find_var(path, nth) over path segments. It returns Found, Missing or Ambiguous. Optional zero-based nth selects a declaration among same-name variables in an unambiguous scope; without it, require exactly one match. Missing/ambiguous rows remain placeholders with their original locator and format, never load a guessed signal, and are reported separately.

    
rows[].formatA translator id ("bit", "hex", …) looked up with Translators::get; unknown ids display the signal's default translator and are reported; retain the requested id on save until the user changes it.

    
viewport, cursor, markersRestored as saved even when outside the trace's time range; drawing intersects the visible range and a marker beyond the end stays addressable.

    
sharedThe shared viewport and cursor plus markers. A panel omits its local viewport or cursor field while that link is on; while off, the field is required (null is a valid cursor). Unlinking always snapshots the current shared value. There is no saved pre-link position to revive.

    
sidebarSession chrome: geometry, filter, selected scope as a segment array (or null), expanded scopes as arrays of segments. Scope resolution also reports ambiguity; unresolved saved paths survive without selecting an arbitrary scope. Global look and feel is not here.

  

  
Excluded on purpose: hover and drag state, animation, load state, window size and position (a preference of the host), theme (a preference), the trace bytes, and anything a VDB defines. The file describes what the user arranged, not what the toolkit computed.






  
Persistence

  
Where, when and how workspaces are saved

  

    
Policy, decided once by the host at startup implemented

      
pub enum Persistence {
    Disabled,                       // tests, --no-workspace, VOLNA_WORKSPACE=off
    Explicit(Target),     // --workspace FILE: load and autosave there
    Storage,                        // VS Code workspaceState
    Auto,                           // default: sidecar beside the trace, fallback dir
}

      
App::new() defaults to Disabled. Only the GPUI native main and the web entry point opt in, so every existing test, the Metal harness, the egui screenshots and the headless suite are isolated by construction; nothing they do can read or write a sidecar, and manually opening example traces cannot affect them.

    
File naming

      
    
        
  • Automatic sidecar: the full trace file name plus .volna.json, e.g. picorv32.vtr.volna.json. Full-name based, so a.vtr and its converted a.fst keep separate workspaces; .json gets syntax highlighting in any editor.
    • 
        
  • Explicit saves: any name the user picks; the dialog suggests <trace>.<label>.volna.json. Opening any *.volna.json from the File menu or command line loads a workspace.
    • 
        
  • *.volna.json is added to the repository .gitignore under volna/volna/examples/.
    • 
      

  

  
Locations and precedence

  
Core selects a restore source before choosing a save target. In automatic mode the host supplies both exact candidates (sidecar and per-user fallback), their locations and write availability; it never parses their JSON. Explicit Open/CLI supplies only the selected file. Missing and unreadable files are distinct results; disabled mode reads neither candidate.

  
    
    
  1. Restore: a valid fallback wins when its supersedes matches the current sidecar. Otherwise use the sidecar and report that the fallback was set aside. With no sidecar, use the fallback even if its former base disappeared. With neither file, start fresh. A read/validation error pauses autosave rather than counting as absence.
    2. 
    
  2. Save: if the fallback was restored, keep saving there even if the trace directory becomes writable. Otherwise use the sidecar when writable, or the fallback when it is not. Keep this target until a successful explicit Open or Save As; permission changes during a session report an error, never silently switch it.
    3. 
    
  3. Fallback location: <data dir>/volna/workspaces/<sha256(canonical trace path)[..16]>.volna.json natively; context.workspaceState keyed by the full trace URI in VS Code. Native data roots are $XDG_DATA_HOME or ~/.local/share, ~/Library/Application Support, and %LOCALAPPDATA%. VS Code's explicit vscode storage setting always writes the fallback.
    4. 
  

  
supersedes is the SHA-256 of the sidecar bytes from which the fallback was based, or null when no sidecar existed. Core computes it over the small workspace file, never the trace. Retain it across edits and reopen; replace it only when starting a new fallback from the selected sidecar. It identifies the base, not the latest sidecar seen at write time. No timestamp comparison, storage registry or conflict-merging service is needed.

  
Timing

  
    
    
  • Revision, not a dirty flag. Commands that change persisted state (rows, layout, focus, links, viewport, cursor, markers, sidebar geometry, format choices) bump a monotonic revision; hover, non-drag pointer motion, animation ticks and menu dismissal do not. The workspace is dirty while revision is ahead of the last acknowledged save.
    • 
    
  • Idle autosave. App::tick(now), the existing explicit clock, emits Event::PersistWorkspace once the app has been dirty and quiet for 1 s; during a viewport animation the timer restarts. This is the debounce example-dock applies at 10 s, shortened because Volna's captures are small.
    • 
    
  • Save tickets. Every PersistWorkspace carries a SaveTicket { target, epoch, revision } and the host answers with the same ticket in App::workspace_saved. Core accepts an acknowledgement only for the outstanding ticket and its workspace epoch; unrelated or already completed tickets are ignored. A Save As ticket is tracked until its write succeeds, then its target becomes active. One write is in flight per editor; a newer snapshot waits. A matching acknowledgement advances acked only to that saved revision, releases the pending write and leaves later edits dirty.
    • 
    
  • Forced points. Closing the trace, opening another, and quitting (on_app_quit) flush a pending save synchronously in native. In VS Code the idle autosave is the primary mechanism; the host additionally asks the webview for a snapshot when the editor is hidden, and on dispose writes the last snapshot it already holds, because the webview is gone by then and cannot be asked.
    • 
    
  • Never while loading. No capture happens between Open and the commit of a restore, so a half-restored state cannot overwrite a good file.
    • 
    
  • Atomic writes natively (temp file in the same directory, then rename); workspace.fs.writeFile in VS Code.
    • 
  

  
Error handling and unavailable state

  
SituationBehaviour

    
No workspace fileStart with one empty panel, as today.

    
Automatic file unreadable, wrong format or newer versionNotice in the status bar with the reason; start fresh; autosave is suspended for this trace until the user saves explicitly or removes the file, so a file from a newer Volna is never overwritten silently.

    
Explicitly opened workspace fails to prepareThe live workspace is untouched: prepare rejected the file before anything was committed. Notice with the reason; the current save target and autosave continue unchanged.

    
Trace referenced by an explicitly opened workspace differs from the open traceResolve the saved trace reference against the workspace location and reject a different resource before commit; a notice directs the user to open that trace first. With no trace open natively, open the referenced trace. Do not import another trace's state and then autosave over its workspace.

    
Signal missingPlaceholder row: name shown dimmed with a "not in trace" badge, no history, no load; kept on save; promoted to a live row if a later trace resolves it.

    
Unknown translator, panel kind or layout idTranslator: default translator and a report entry. Panel kind: opaque placeholder panel. Layout: prepare fails as a whole; for an automatic file that means a fresh start with autosave suspended, for an explicit open it means nothing changes.

    
Times outside the trace rangeKept; drawing intersects the visible trace range.

    
Save fails (disk full, permission lost)App::workspace_saved carries the error; the workspace stays dirty, a "workspace not saved" notice stays up, and the next idle point retries the same target. The target is never switched silently; "Save As…" is the way out. The status notice opens a scrollable details dialog.

    
Two viewers on one traceLast writer wins for the sidecar. Not mediated in this scope; explicit "Save As" gives each person their own file. Cross-process locking and conflict prompts are deliberately deferred until there is evidence they are needed.

  

  
Restoration is two steps so that failure is harmless. prepare parses, checks format and version, validates the layout tree, resolves every row to a VarId or a placeholder and produces a RestorePlan without touching the live App. commit then installs panels, shared values, markers and sidebar state together, bumps the document generation to reject stale loads and callbacks, and queues unique resolved signals across panels. The app controller separately advances the save epoch. Every commit returns a RestoreReport listing what could not be applied. The report is surfaced as a status-bar notice with a "details" popup and is asserted in tests.

  
Global preferences implemented

  
Look and feel that is not part of any session lives in <config dir>/volna/preferences.json: theme name, default link flags for new panels, autosave on or off, the recent traces and workspaces list. The config dir is $XDG_CONFIG_HOME/volna or ~/.config/volna on Linux and macOS (the goal's example, and the convention for command-line tools on both), %APPDATA%\volna on Windows; VOLNA_CONFIG_DIR overrides it. The model is a serde struct in volna-core::workspace::prefs; reading and writing are host code. Inside VS Code the theme comes from the host and the remaining preferences are contributed volna.* settings passed with the open message, so nothing is written to ~/.config by the extension.

  
Command line implemented

  
volna [FILE.vtr|FILE.fst|FILE.volna.json] [--synthetic N]
      [--workspace PATH]        // load and autosave this workspace file, ignoring sidecars
      [--no-workspace]          // never read or write workspace files this run
      [--config-dir DIR]        // preferences location (also VOLNA_CONFIG_DIR)
// environment: VOLNA_WORKSPACE=off | PATH, VOLNA_CONFIG_DIR=DIR; check.sh exports VOLNA_WORKSPACE=off

  
The GPUI native parser accepts these flags. The egui frontend keeps persistence disabled and receives only compatibility changes required by the core refactor.






  
Flows

  
Restoration and saving on both hosts

  
The core runs the same sequence in both; only the boxes that move bytes differ.

  

    
Native (GPUI)

      
    
        
  1. main.rs parses flags and preferences, configures persistence on App::new(), and opens the trace with its canonical resource URI.
    2. 
        
  2. The open completes (LoadResult::Opened); the core installs the session and emits Event::LoadWorkspace{key: Sidecar(path) | Explicit(path)}.
    3. 
        
  3. The GPUI host reads the requested candidate files off the UI thread and returns WorkspaceCandidates: opaque JSON, location, write availability and distinct missing/error results. Core applies the source/target rules above.
    4. 
        
  4. The core runs prepare: parse, validate the tree, resolve rows to VarIds or placeholders. On failure it emits Notice and leaves the default single panel in place. On success it runs commit: installs panels, shared values, markers and sidebar state, bumps the epoch, queues loads for visible rows, and emits LayoutChanged plus Notice(report).
    5. 
        
  5. The dock adapter installs the layout; loads arrive through the existing deliver path and fan into every panel showing the signal.
    6. 
        
  6. Edits bump the revision; after 1 s idle tick emits PersistWorkspace{ticket, bytes}; the host writes atomically and replies App::workspace_saved(ticket, error, now). Quit and close flush.
    7. 
      

    
VS Code extension

      
    
        
  1. VS Code resolves the custom editor (first open or workspace restore) and calls resolveCustomEditor.
    2. 
        
  2. extension.js reads the trace bytes and both exact workspace candidates (sidecar and URI-keyed workspaceState), or neither when disabled. It posts open {traceUri, name, bytes, candidates, settings}; Rust selects the source and target using the same rules as native.
    3. 
        
  3. The wasm bridge opens the bytes through OpenSpec::Bytes and, when the open completes, answers the core's LoadWorkspace event with the candidates it was handed. No second round trip.
    4. 
        
  4. Same core prepare and commit as native, steps 4 and 5.
    5. 
        
  5. On PersistWorkspace the bridge posts workspace {ticket, json}; the host keeps it as the latest snapshot for this editor, writes ticket.target with workspace.fs.writeFile or workspaceState.update, and answers saved {ticket, error?}. Because the extension host runs beside the file in remote sessions, the sidecar lands next to the remote trace without any transfer.
    6. 
        
  6. onDidChangeViewState (hidden) sends requestWorkspace so the latest edits are captured before the webview may be discarded. onDidDispose writes the latest snapshot the host already holds and asks the webview for nothing. Reopening the VS Code window returns to step 1 with the saved bytes.
    7. 
      

  

  
Explicit actions use the same core prepare/commit and ticketed writes. Open Workspace supplies the file location with its bytes; after successful prepare, flush the old dirty workspace, then commit state and the new target together. A failed prepare or flush leaves both unchanged. Save As returns the chosen location to core, waits for outstanding writes, and writes a snapshot with a ticket naming that destination. Switch the active target only after success; newer edits remain dirty and save there next. Failure keeps the old target. Rebase the trace reference against the new location; fallback entries use an absolute trace URI so host storage needs no directory semantics. Hosts always write ticket.target, including explicit files; they never keep a separate authoritative target.

Core API
Commands, codec and host contract


The source is authoritative. Hosts configure persistence and supply a durable trace URI with App::open_resource. Existing consumers can use App::new without storage or filesystem effects.


app.configure_persistence(Persistence::Auto);
app.open_resource(spec, trace_uri);
// Handle Event::LoadWorkspace: read bounded candidates, then:
app.restore_candidates(trace_uri, sidecar, fallback);
// Handle Event::PersistWorkspace { ticket, bytes }: write ticket.target, then:
app.workspace_saved(ticket, error, now);
// Dialog results:
app.open_workspace(target, &bytes)?;
app.save_workspace(Some(destination)); // None saves the active target


Workspace::capture(&app, trace_path, supersedes) produces the durable model; to_bytes and parse are bounded JSON operations. prepare(&app, expected_trace, workspace_location) returns a RestorePlan; commit(&mut app) installs it only if the document generation still matches. The app controller adds save-before-transition ordering around explicit restore.


Command::Panels(PanelsCommand) covers split, new tab, close, close others, focus, next/previous/index, rename, link toggle and revision-checked layout replacement. Pointer and format-menu commands name a panel. Frontends use handle_if_current(generation, command) for delayed input. Group zoom belongs to the dock and is transient.


Event::Changed invalidates waveform entities. Event::LayoutChanged { revision } updates the dock mirror and keyboard focus. Repainting a wave does not rebuild dock chrome. TraceClosed { trace_uri } lets VS Code close the matching custom-editor tab; Quit is emitted after the required save completes.


The native store and vscode-ext/workspace.js implement transport only. Wasm exports open_resource, workspace_message and dispatch_command; existing open_trace, theme and debug exports remain available to a plain browser host with persistence disabled.






  
Decisions

  
Trade-offs

  
DecisionChosenBecauseCost

    
Where the layout tree livesCore, mirrored into the dockFrontend-neutral saved state (AGENTS.md "Volna direction" 2); egui and tests read the same tree; library upgrades cannot break filesA translation layer and a revision guard (about 150 lines)

    
Cursor ownershipPer panel with a link flag; markers sharedThe requirement asks for independent cursors; the flag reproduces Surfer's shared cursor by defaultDocument::shared.cursor moves; every current caller changes (mechanical)

    
Sync groupsTwo global link flagsCovers "follow" and "independent" with no group UI; groups require a versioned format changeCannot have separate linked sets A+B and C+D

    
Panel identity in filesMonotonic PanelId written to the fileLayout references and future cross-panel references (source ↔ waves) need stable idsIds must be validated on load

    
Signal referencesHierarchy path as segments, optional nthNames are the only identity VTR promises across runs; segments need no escaping contract for identifiers that contain dotsNeeds Hierarchy::find_var; renames break rows (placeholders keep them visible)

    
Shared navigationOne value on the document, read through by linked panelsA single copy cannot disagree; no propagation pass; re-linking always has a value to adoptEvery viewport/cursor read goes through an "effective" accessor

    
Save acknowledgementTicket of target, epoch and revisionA late or stale acknowledgement can never mark newer edits, another target, or a replaced workspace as savedThree fields on two messages

    
RestorationPrepare, then commitA bad file, automatic or explicit, never disturbs a healthy workspaceA RestorePlan type between the two steps

    
FormatJSON via serde_jsonAlready a dependency, readable in VS Code, diffable for sharing; RON would add a crate for no user benefitSlightly larger files than a binary format; irrelevant at this size

    
Sidecar name<file>.volna.jsonDistinguishes a.vtr from a.fst; sortable next to the trace; ignorable by globLong names

    
Automatic saveIdle autosave, on by defaultThe requirement; matches VS Code's own editor-state behaviourFiles appear beside traces; documented, gitignored for examples, disabled in tests and by flag

    
Read-only trace directoryPer-user fallback dir keyed by path hash, retained when restoredShared CI artefacts are read-only; losing the session there would make the feature unreliableA second location to explain; core checks the fallback's original sidecar fingerprint

    
Preferences location~/.config/volna on Linux and macOSGoal's example; command-line tool convention on macOS as wellNot the macOS GUI convention (Library/Application Support), which is used only for the workspace fallback data

    
VS Code storageSidecar through workspace.fs, workspaceState fallbackSame file as native, remote-safe, shareable; the fallback covers read-only and virtual file systemsMultiple editors per document disabled to avoid write races

    
Hidden headerRenderer wrapper over DockSkin, exercised by native and browser testsOne host path for one and many panels; identical geometry to todayForwarding boilerplate; if the seam falls short, a small renderer hook rather than a bypass

    
eguiFocused panel only, no persistenceAGENTS.md: keep it building with its minimal feature setSessions with several panels show one of them in egui; that is allowed by the direction ("without requiring that frontend to implement every view")

Scope boundaries
Additional panel kinds, named link groups, undo close, cross-process file locking, floating windows, workspace version migrations and egui feature parity remain outside this implementation. Workspace data does not enter VTR, VDB or the raw query protocol. The native host uses atomic replacement; remote VS Code writes follow the filesystem provider’s guarantees. Competing processes retain last-writer-wins behavior.
