Dockable waveform panels and persistent workspaces for Volna

Several waveform panels over one trace, arranged in VS Code-style splits and tabs, with linked or independent viewports and cursors, and a workspace file that brings the whole debugging session back when the trace is reopened, natively or inside VS Code.

existing already in the repository proposed new in this design library provided by gpui-kit 0.6.1

Research and design only; nothing here is implemented. Citations point at files in this repository, the pinned Surfer fork under ext/surfer, and the gpui-kit 0.6.1 sources in the cargo registry.

Recommendation

The simplest coherent design

Panels live in the core

proposed volna-core gains a Panels model: a toolkit-neutral layout tree of splits and tab groups, a map of panels keyed by a never-recycled PanelId, and a focused panel. Each waveform panel owns a WaveModel (rows, viewport, cursor, selection). The Document keeps what every panel shares: the session, markers, translators and load bookkeeping. Keyboard actions go to the focused panel; pointer events name their panel.

Two link flags per panel, no groups

proposed Synchronisation is two toggles per panel, follow viewport and follow cursor, shown as icon buttons in the panel header. Linked panels share one viewport and one cursor stored on the document; an unlinked panel keeps its own. With a single panel the header is hidden and the same toggles sit in the View menu and status bar, where they are also reachable by keyboard.

Reuse gpui-kit's dock engine

library The GPUI frontend hosts the central area in gpui-kit's DockArea, which already provides nested splits, tab groups, drag-to-reorder, drag-to-split, zoom and a serde round trip. proposed A thin adapter mirrors the core layout into the dock and translates dock edits back; a wrapper renderer hides the tab bar when the centre holds one panel, so today's viewer looks unchanged.

One workspace format, thin hosts

proposed volna-core::workspace defines a versioned JSON document, captures it from App, restores it by resolving signal paths against the open hierarchy, and schedules autosaves. Hosts only move bytes: the native app writes trace.vtr.volna.json beside the trace, the VS Code extension writes the same file through workspace.fs so remote files work, and both fall back to per-user storage when the trace directory is read-only.

What stays out. Nothing presentational enters VTR, VDB or the future raw-data query protocol; workspace files are a client-side annotation beside the trace. The egui frontend keeps rendering exactly one panel, the focused one, and gains no persistence. No new panel kinds ship in this scope, but the panel model, workspace format and dock registry are keyed by kind so transaction, source and pipeline panels slot in later.

Facts from the VS Code extension guides that shape the host adapter:

  • Webview state. getState/setState "is persisted even after the webview content itself is destroyed when a webview panel becomes hidden", but "the state is destroyed when the webview panel is destroyed". They are "the preferred way to persist state, as they have much lower performance overhead than retainContextWhenHidden", which "has high memory overhead and should only be used when other persistence techniques will not work". (Webview guide, Persistence.)
  • Restart. A WebviewPanelSerializer restores plain webview panels across restarts. Custom editors are editor inputs: VS Code reopens them with the workspace and asks the provider to openCustomDocument and resolveCustomEditor again, so restoring a Volna editor is the same code path as the first open. The custom editor guide recommends workspace.fs for writing files, which also covers remote and virtual workspaces.
  • Multiple editors. "By default, VS Code only allows there to be one editor for each custom document"; Volna currently opts into supportsMultipleEditorsPerDocument: true. With internal panels covering the split use case, two editors autosaving one sidecar would race, so the proposal turns this off.
  • Read-only provider. Volna's traces are never edited, so the provider remains the read-only shape: no backup, save or revert hooks. Workspace files are separate from the document and never mark the editor dirty.
Panels

Panel model and interactions

Core types proposed

// volna-core/src/panels/mod.rs
pub struct PanelId(u64);                     // monotonic per App, never recycled
pub enum Axis { Horizontal, Vertical }

pub enum Layout {
    Tabs  { panels: Vec<PanelId>, active: usize },          // leaves only, like Surfer and gpui-base
    Split { axis: Axis, sizes: Vec<f32>, children: Vec<Layout> }, // sizes are fractions summing to 1
}

pub enum PanelKind { Waves(WaveModel) }      // later: Transactions(..), Source(..), Pipeline(..)
impl PanelKind { pub fn name(&self) -> &'static str { "waves" } }

pub struct Link { pub viewport: bool, pub cursor: bool }   // default: both true

pub struct Panel { pub id: PanelId, pub title: Option<String>, pub link: Link, pub kind: PanelKind }

pub struct Panels {
    layout: Layout,
    panels: BTreeMap<PanelId, Panel>,
    focused: PanelId,                        // always a panel in `layout`
    next_id: u64,
}

Invariants the core enforces after every command: the layout references every panel exactly once, tab groups contain at least one panel, splits contain at least two children, sizes are normalised, and at least one waveform panel exists. Closing the last panel empties it instead of removing it, so the single-panel view is always available and the hidden-header rule below never has to handle zero panels.

What moves, what stays

Shared on Document

  • existing session, translators, hierarchy access, load generations and pending set
  • existing markers, now with an id and optional label so chips are addressable and a workspace can name them (Marker{id, time, label})
  • proposed linked: Linked { viewport: Viewport, cursor: Option<u64> }, the values every linked panel displays

Per panel on WaveModel

  • existing rows (DisplayedSignal), selection, viewport and animation, scroll, column widths, hover and drag state, format menu
  • proposed cursor: Option<u64> moves here from Document
  • proposed missing: bool on a row that could not be resolved on restore (placeholder)

Load fan-out changes from "the one model" to "every waveform panel that shows this signal": App::deliver iterates the panels, and histories stay shared Arcs across panels exactly as they are shared across duplicate rows today. A history is released when the last row in any panel drops it.

Synchronisation semantics proposed

  • Two flags per panel. link.viewport and link.cursor, both on by default. New panels inherit the flags of the panel they were split from.
  • Linked means "displays the document value". When a linked panel pans, zooms, fits, animates or sets the cursor, the core writes the new value into doc.linked and copies it into every other linked panel, animation target included (WaveModel::follow(&source)). Unlinked panels are untouched.
  • Toggling on snaps. Turning a flag on copies the document value into the panel. Turning it off leaves the panel where it is; it now moves alone.
  • Edge stepping and "centre on cursor" operate on the focused panel's own cursor and viewport and then propagate through the same rule, so linked panels follow.
  • Markers are always shared; M adds a marker at the focused panel's cursor.
  • One panel: the flags exist but have no visible effect. They are kept so a later split starts in the expected state.

This is deliberately weaker than named sync groups (as in Verdi or GTKWave "locked" windows): one global link per dimension covers the two common cases, "everything follows" and "this one is my independent zoomed-in view", and it needs no group management UI. Groups can be added later by replacing the bools with a GroupId without changing the file format's shape (the field becomes an integer).

Visual rules

  • Single panel in the centre: no header, no outline. The element tree, geometry and default chrome match today's viewer, so the Metal and egui screenshot baselines stay valid.
  • Two or more panels: each tab group shows a tab strip (VS Code-style: active tab in surface colour with an accent top edge; inactive tabs dimmed). The focused panel's tab and a 1 px accent outline around its body mark keyboard focus; unfocused panels draw their cursor line with the wave_cursor_inactive token at reduced contrast so the eye finds the active panel. All colours are theme tokens (theme::Theme), so VS Code themes and One Dark both resolve them.
  • Status bar shows the focused panel's name and its two link states as chips when more than one panel exists; the trace range, cursor time and resolution shown today refer to the focused panel.

Docking library

  
Integrating gpui-kit's DockArea

  
The engine fits: it already implements the tree editing, drag semantics and serialisation that would otherwise be several thousand lines, its appearance is replaceable, it has no native-only code, and Volna already links it. The integration keeps the core tree authoritative and treats the dock as a view of it, following Surfer's adapter pattern.

Round trip and loop guard

  
    
    
  1. Core → dock. After any command that changes Panels::layout, the core emits Event::LayoutChanged{revision}. The adapter rebuilds a DockLayout from the tree and calls set_center, recording revision.
    2. 
    
  2. Dock → core. On DockEvent::LayoutChanged the adapter calls dump(), walks the PanelState tree ("StackPanel" → Split with sizes normalised to fractions, "TabPanel" → Tabs, "volna.waves" → the PanelId in its info) and sends Command::Panels(SetLayout{tree, from_revision}). The core validates (every id known, no duplicates) and adopts it, or rejects it and re-emits its own tree so the dock resynchronises.
    3. 
    
  3. Guard. LayoutChanged raised by the adapter's own set_center is ignored by comparing the dumped tree with the tree installed at that revision. This is the same idea as Surfer's LayoutAdapter revision check.

Hiding the header for one panel

  
PanelStyle::Auto still draws a 30 px title row. Volna installs VolnaDockRenderer, a DockAreaRenderer that forwards every hook to the stock DockSkin and wraps its tab_group_renderer(): when the centre tree has exactly one panel, render_tab_bar returns an empty element and frame drops the group border, so the panel body starts at the same y-offset as today's WaveTable. TabGroupSkin is crate-private but reachable through the trait, so this is composition, not a fork. If the wrapper proves brittle, the fallback is to bypass the dock entirely while one panel exists and render the cached WavePanelView directly; the entity and its state are the same in both hosts.

Workspace data model

  
The workspace file

  
A JSON document owned by volna-core::workspace, written with serde_json, human-readable and diffable so colleagues can share and review it. Times are integers in the trace's own timescale units, matching SignalHistory and Marker. Signals are referenced by full hierarchical name, the identity VTR guarantees to external databases and the one Hierarchy::full_name produces today.

FieldRule

    
format, versionBoth checked before anything else. A different format string or a newer major version rejects the file with a notice; older versions are not migrated during the research phase (GOAL.md §8). The file is left untouched.

    
traceIdentity of the trace the workspace was captured from. On restore the name and timescale are compared: a different timescale warns and restores times unchanged; a different name warns but proceeds, because renamed traces are common. design_id is compared when both sides have it.

    
layout, focusedThe same tree as Panels::layout; sizes are fractions. An invalid tree (unknown id, duplicate, empty group) fails restore as a whole and reports why.

    
panels[].kind, versionPanels are decoded into PanelKind by name; an unknown kind or newer version is kept as raw JSON (serde_json::value::RawValue) in a placeholder panel that draws "unsupported panel" and is written back verbatim, so a workspace saved by a newer Volna survives a round trip through an older one.

    
rows[].signalResolved through proposed Hierarchy::find_var(path: &str) -> Option<VarId>, a segment walk from the roots added at the owning layer rather than a side table in the workspace code. Unresolved rows become placeholders (missing: true, no load) and are saved back unchanged.

    
rows[].formatA translator id ("bit", "hex", …) looked up with Translators::get; unknown ids fall back to the signal's default translator and are reported.

    
viewport, cursor, markersRestored as saved even when outside the trace's time range; the viewport clamp already handles this at paint time and a marker beyond the end stays addressable.

    
sharedThe linked viewport and cursor plus markers. Linked panels take these values after restore regardless of their saved per-panel values, which are kept for the moment they unlink.

    
sidebarChrome that belongs to the session: visibility, widths, selected scope and expanded scopes by path, filter text. Global look and feel is not here.

  

  
Excluded on purpose: hover and drag state, animation, load state, window size and position (a preference of the host), theme (a preference), the trace bytes, and anything a VDB defines. The file describes what the user arranged, not what the toolkit computed.






  
Persistence

  
Where, when and how workspaces are saved

  

    
Policy, decided once by the host at startup proposed

      
pub enum Persistence {
    Disabled,                       // tests, --no-workspace, VOLNA_WORKSPACE=off
    Explicit { path: PathBuf },     // --workspace FILE: load and autosave there
    Auto,                           // default: sidecar beside the trace, fallback dir
}

      
App::new() defaults to Disabled. Only the two native mains and the web entry point opt in, so every existing test, the Metal harness, the egui screenshots and the headless suite are isolated by construction; nothing they do can read or write a sidecar, and manually opening example traces cannot affect them.

    
File naming

      
    
        
  • Automatic sidecar: the full trace file name plus .volna.json, e.g. picorv32.vtr.volna.json. Full-name based, so a.vtr and its converted a.fst keep separate workspaces; .json gets syntax highlighting in any editor.
    • 
        
  • Explicit saves: any name the user picks; the dialog suggests <trace>.<label>.volna.json. Opening any *.volna.json from the File menu or command line loads a workspace.
    • 
        
  • *.volna.json is added to the repository .gitignore under volna/volna/examples/.
    • 
      

  

  
Locations and precedence

  
    
    
  1. Explicit path from --workspace or an "Open Workspace…" action.
    2. 
    
  2. Sidecar next to the trace, when the directory is writable.
    3. 
    
  3. Per-user fallback when the trace lives on a read-only share, which is the norm for CI artefacts: <data dir>/volna/workspaces/<sha256(canonical trace path)[..16]>.volna.json, where the data dir is $XDG_DATA_HOME or ~/.local/share on Linux, ~/Library/Application Support on macOS, %LOCALAPPDATA% on Windows. The file records the original path in trace.path so the mapping is auditable.
    4. 
  

  
On load the first location that exists wins; on save the first location that is writable wins. A sidecar that exists but cannot be written falls through to the fallback with a one-time notice.

  
Timing

  
    
    
  • Dirty tracking in the core. Commands that change persisted state (rows, layout, focus, links, viewport, cursor, markers, sidebar geometry, format choices) set a dirty flag; hover, pointer-move, animation ticks and menu dismissal do not.
    • 
    
  • Idle autosave. App::tick(now), the existing explicit clock, emits Event::PersistWorkspace once the app has been dirty and quiet for 1 s; during a viewport animation the timer restarts. This is the debounce example-dock applies at 10 s, shortened because Volna's captures are small.
    • 
    
  • Forced points. Closing the trace, opening another, quitting (on_app_quit natively, dispose in VS Code) and hiding the editor tab all flush a pending save synchronously.
    • 
    
  • Never while loading. No capture happens between Open and the restore completing, so a half-restored state cannot overwrite a good file.
    • 
    
  • Atomic writes natively (temp file in the same directory, then rename); workspace.fs.writeFile in VS Code.
    • 
  

  
Error handling and unavailable state

  
SituationBehaviour

    
No workspace fileStart with one empty panel, as today.

    
File unreadable, wrong format or newer versionNotice in the status bar with the reason; start fresh; autosave is suspended for this trace until the user saves explicitly or removes the file, so a file from a newer Volna is never overwritten silently.

    
Trace referenced by an explicitly opened workspace differs from the open traceKeep the open trace (Surfer's rule); restore layout, panels, markers and links against it; report unresolved signals. With no trace open natively, open trace.path resolved against the workspace file's directory.

    
Signal missingPlaceholder row: name shown dimmed with a "not in trace" badge, no history, no load; kept on save; promoted to a live row if a later trace resolves it.

    
Unknown translator, panel kind or layout idTranslator: default translator and a report entry. Panel kind: opaque placeholder panel. Layout: whole restore rejected with a notice, fresh start, autosave suspended.

    
Times outside the trace rangeKept; painting clamps.

    
Save fails (disk full, permission lost)Notice; retry at the next idle point; explicit save reports the error in the dialog.

    
Two viewers on one traceLast writer wins for the sidecar. Not mediated in this scope; explicit "Save As" gives each person their own file.

  

  
Every restore returns a RestoreReport listing what could not be applied. The report is surfaced as a status-bar notice with a "details" popup and is asserted in tests.

  
Global preferences proposed

  
Look and feel that is not part of any session lives in <config dir>/volna/preferences.json: theme name, default link flags for new panels, autosave on or off, the recent traces and workspaces list. The config dir is $XDG_CONFIG_HOME/volna or ~/.config/volna on Linux and macOS (the goal's example, and the convention for command-line tools on both), %APPDATA%\volna on Windows; VOLNA_CONFIG_DIR overrides it. The model is a serde struct in volna-core::workspace::prefs; reading and writing are host code. Inside VS Code the theme comes from the host and the remaining preferences are contributed volna.* settings passed with the open message, so nothing is written to ~/.config by the extension.

  
Command line proposed

  
volna [FILE.vtr|FILE.fst|FILE.volna.json] [--synthetic N]
      [--workspace PATH]        // load and autosave this workspace file, ignoring sidecars
      [--no-workspace]          // never read or write workspace files this run
      [--config-dir DIR]        // preferences location (also VOLNA_CONFIG_DIR)
// environment: VOLNA_WORKSPACE=off | PATH, VOLNA_CONFIG_DIR=DIR; check.sh exports VOLNA_WORKSPACE=off

  
The same hand-rolled parser is extended in both native mains; a clap dependency is not needed for five flags. volna-egui accepts and ignores the workspace flags so scripts can pass the same arguments to both.






  
Flows

  
Restoration and saving on both hosts

  
The core runs the same sequence in both; only the boxes that move bytes differ.

  

    
Native (GPUI or egui)

      
    
        
  1. main.rs parses flags, builds Persistence and App::new_with(persistence), opens the trace with open_path.
    2. 
        
  2. The open completes (LoadResult::Opened); the core installs the session and emits Event::LoadWorkspace{key: Sidecar(path) | Explicit(path)}.
    3. 
        
  3. The GPUI Workspace resolves the key through the location precedence, reads the bytes off the UI thread and replies Command::RestoreWorkspace(Some(json)) or None.
    4. 
        
  4. The core parses and validates, builds panels, resolves rows to VarIds, queues signal loads under the current generation, sets links, markers and sidebar state, and emits LayoutChanged plus Notice(report).
    5. 
        
  5. The dock adapter installs the layout; loads arrive through the existing deliver path and fan into every panel showing the signal.
    6. 
        
  6. Edits mark the core dirty; after 1 s idle tick emits PersistWorkspace{target, json}; the host writes atomically. Quit and close flush.
    7. 
      

    
VS Code extension

      
    
        
  1. VS Code resolves the custom editor (first open or workspace restore) and calls resolveCustomEditor.
    2. 
        
  2. extension.js reads the trace bytes and, unless volna.workspace.autosave is off, tries <uri>.volna.json through workspace.fs.readFile, then context.workspaceState under volna.workspace:<uri>. It posts open {name, bytes, workspace, settings}.
    3. 
        
  3. The wasm bridge opens the bytes through OpenSpec::Bytes and, when the open completes, answers the core's LoadWorkspace event immediately with the JSON it was handed. No second round trip.
    4. 
        
  4. Same core restore as native, steps 4 and 5.
    5. 
        
  5. On PersistWorkspace the bridge posts workspace {json}; the host writes the sidecar with workspace.fs.writeFile, falling back to workspaceState if the write fails or the setting selects it. Because the extension host runs beside the file in remote sessions, the sidecar lands next to the remote trace without any transfer.
    6. 
        
  6. onDidChangeViewState (hidden) and webviewPanel.onDidDispose request a final workspace flush; reopening the VS Code window returns to step 1 with the saved bytes.
    7. 
      

  

  
Explicit actions use the same primitives: "Save Workspace As…" emits Event::SaveWorkspaceDialog{suggested}; the host shows its dialog (GPUI prompt_for_new_path, VS Code showSaveDialog) and writes the capture it then requests. "Open Workspace…" reads a chosen file and sends Command::RestoreWorkspace; if the trace named in it differs from the open one, the open trace is kept and the report says so.

// vscode-ext/extension.js — host side, sketch
async function resolveCustomEditor(document, panel, context) {
  wire(panel.webview, context, document.uri);
  const settings = vscode.workspace.getConfiguration("volna");
  const bytes = await vscode.workspace.fs.readFile(document.uri);
  const workspace = await readWorkspace(document.uri, settings);        // sidecar → workspaceState → null
  panel.webview.postMessage({ type: "open", name: basename(document.uri), bytes: bytes.buffer, workspace, settings: pick(settings) });
  panel.onDidChangeViewState(e => { if (!e.webviewPanel.visible) panel.webview.postMessage({ type: "requestWorkspace" }); });
  panel.onDidDispose(() => flushPending(document.uri));
}
function sidecarUri(uri) { return uri.with({ path: uri.path + ".volna.json" }); }
async function writeWorkspace(uri, json, settings) {
  if (settings.get("workspace.autosave") === "off") return;
  try { await vscode.workspace.fs.writeFile(sidecarUri(uri), Buffer.from(json)); }
  catch { await context.workspaceState.update("volna.workspace:" + uri.toString(), json); }
}

  • Workspace-aware remote sessions: when bounded window queries land, the restore path issues window requests instead of whole histories; the file format does not change.
    • 
    

  

  
Non-goals

  
    
    
  • Editing or annotating traces; nothing is written into VTR or VDB.
    • 
    
  • Multi-window tear-off, floating tiles, a top dock.
    • 
    
  • Migration of older workspace versions during the research phase.
    • 
    
  • Feature parity in volna-egui.
