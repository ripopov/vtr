## Summary

- **Size.** VTR (zstd-3) is smaller than the smallest FST variant on 8 of 8 signal workloads: scr1_axi 51%, rsa256 98%, rsa256_long 98%, c910_coremark 63%, scr1_x8 47%, long_sparse 61%, many_active 69%, wide_bus 97% of the best FST size.
- **Write speed.** VTR (background encoder) is faster than the fastest FST writer on 8 of 8 workloads: scr1_axi 2.13x, rsa256 1.63x, rsa256_long 1.57x, c910_coremark 1.64x, scr1_x8 1.88x, long_sparse 1.69x, many_active 1.50x, wide_bus 1.13x. Inline encoder: 1.35x, 1.45x, 1.58x, 1.08x, 1.22x, 1.39x, 1.18x, 1.12x.
- **Read and navigation** (VTR speed-up over wellen, min-max across workloads; sub-millisecond queries are noisy): open 2.0-798.3x, load 1 signal 3.9-11.7x, load 10 3.4-9.0x, load 100 2.5-10.5x, load 1000 1.2-3.6x, value at time 2.4-6.5x, window scan 3.9-11.4x, condition search 2.6-6.1x, stream all 2.3-75.8x. VTR is faster in every query on every workload.
- **Parity.** Values and change counts identical between wellen and VTR on all workloads: yes.
- **Information check.** Source FST and VTR files converted to VCD carry the same value changes, in total and per signal, on scr1_axi (20,977,928 changes), rsa256 (1,621,415 changes), rsa256_long (16,212,012 changes), c910_coremark (596,626,011 changes): yes.
- **Simulator-integrated (Verilator --trace-fst vs --trace-vtr, whole design traced).** rsa256: tracing adds 0.20 s with FST and 0.14 s with VTR to a 0.00 s simulation (1.43x less trace cost), VTR file 96% of Verilator's FST; rsa256_long: tracing adds 1.58 s with FST and 1.06 s with VTR to a 0.05 s simulation (1.49x less trace cost), VTR file 96% of Verilator's FST; c910_coremark: tracing adds 51.86 s with FST and 43.97 s with VTR to a 12.15 s simulation (1.18x less trace cost), VTR file 50% of Verilator's FST. Files written by the two Verilator backends read back identically: yes.
- **Transactions.** tlm_1m size 34% of FTR-LZ4, write speed 1.79x FTR-LZ4 and 1.30x uncompressed FTR; ooo_1m size 18% of FTR-LZ4, write speed 1.73x FTR-LZ4; kanata_sample2 size 18% of FTR-LZ4, write speed 1.00x FTR-LZ4.

## Workload descriptions

- **scr1_axi**: SCR1 RISC-V core with AXI testbench, Verilator FST fixture from the wavepeek repository (real RTL, small design)
- **rsa256**: RSA-256 Montgomery multiplier from libfstwriter's integration tests driven with continuous pseudo-random operands (bench/workloads/rsa256/RSA_bench_tb.sv), Verilator, 200k cycles (real RTL, wide datapaths)
- **rsa256_long**: Same RSA-256 design and driver, 2M cycles (real RTL, long simulation)
- **c910_coremark**: pulp-c910 (T-Head openC910: 3-wide superscalar out-of-order RISC-V core with L1 caches, MMU and AXI SoC from ext/pulp-c910) running one CoreMark iteration under Verilator, every signal of the design traced (real RTL, large design)
