Analog plots in the waveform panel

Draw a bus or a real signal as a line plot in its own row, on the same time axis as the digital signals around it. One key turns it on, and the format the row already has decides the numbers.

Implemented in Volna; measurements and deviations are in docs/RATIONALE.md (“Volna analog waves”). Before it, a 16-bit filter output showed as a band of hexadecimal values that was too dense to read. Questions such as where does the amplitude drop? or does the FIFO fill before every overflow? needed an export and an external plot. The design reuses the row list, the height presets, the format menu and the wave gestures that already exist, and it adds one drawing mode. Related documents: transaction-waveforms.html (another row kind on the same canvas) and user-settings.html.

Try it

This is a mock of the Waves panel on a small receive chain. adc_in is a real-valued input from a behavioural model: a 250 kHz tone that fades at 55 µs, with a one-sample glitch at 42.01 µs. adc_code is its 12-bit signed sample, fir_out is an 8-tap filter of that sample, and agc_gain reacts to the fade. A FIFO fill level runs next to its overflow flag. The trace is generated for this page: 100 µs with a new sample every 10 ns.

How it works

  1. Analog is a way to draw a row.Press A on the selected rows, or choose Analog in the Draw section of the format menu, which opens from the row's format badge. The row keeps everything else: selection, drag to reorder, cut, copy and paste, the Height menu, removal and its workspace entry. Only vectors and reals can be drawn this way. Bit, event and text rows show no Draw section, and A skips them. Real signals are added as plots from the start, because a column of floating-point text is rarely readable. A turns one back into text.
  2. The format decides the numbers.Unsigned, Hexadecimal and Binary plot the unsigned value, Signed plots the two's-complement value, and IEEE float and Real plot the float. The value column and the axis labels use the same format. A signed bus left in Hexadecimal therefore plots as a sawtooth that wraps at zero. Vivado and Questa both warn about this trap. Here the fix is two lines lower in the same menu, and the plot glides to its new range.
  3. A taller row from the same presets.Turning analog on makes a 1× row 3×, and turning it off restores 1×. Heights stay the ordinary presets (1×, 2×, 3×, 4× and 8×), so rows keep the grid rhythm. A new gesture works for every row: drag the bottom edge of a name cell to resize it. It snaps to the presets and applies to the whole selection. Axis labels appear from 2× up.
  4. Step or linear.Step (sample-and-hold) is the default for vectors. A register holds its value until the next change, and step draws exactly that. Linear joins consecutive samples and is the default for reals, which usually sample a continuous quantity. When you zoom in far enough, linear marks every sample with a dot, so an interpolated segment is never mistaken for recorded data.
  5. Three ranges, all automatic.Whole trace is the default. It fits the signal's minimum and maximum over the whole recording, so the plot does not move while you pan. Visible window fits only what is on screen and glides to the new range as you pan or zoom. Use it to read a small signal in a quiet stretch. Type limits uses the full range of the vector type, for example 0 to 63 for a 6-bit fill level, which suits levels and counters. Labels at the top and bottom show the range, and a dashed line marks zero when zero lies inside it. None of the three ranges ever clips a value.
  6. Nothing is lost when you zoom out.When several changes fall into one pixel column, the column is drawn from its minimum to its maximum and joins its neighbours at its entry and exit values. The picture is the same as drawing every sample, so a one-sample glitch stays visible at any zoom. Undefined (X or Z) stretches break the line and are painted in the undefined colour, as on buses.
  7. Reading values.The cursor puts a dot on every plot, and the value column shows the value at the cursor in the row's format. Hovering shows the value under the pointer. In a column that holds many changes, it shows that column's minimum and maximum and the number of changes instead. Click snapping, T and Shift+←/→ work as they do on digital rows.

Drawing a million samples in a thousand pixels

The input adc_in holds 10,000 samples, and the demo draws them into a few hundred pixels. There are two common ways to reduce them, and only one of them is honest. Both figures below draw the same data with the same range.

The proposed method is M4 (Jugel et al., VLDB 2014). For each pixel column it keeps the first, last, minimum and maximum values, which is provably enough to draw a line chart with no pixel error. It is also how Volna's bus and bit painters treat dense columns today: a column with many changes becomes a band instead of being sampled. GTKWave skips samples, much like the right-hand figure. LTTB-style downsampling looks smooth but is not pixel-exact and can drop a spike. Surfer and PulseView both draw per-column min/max, from a precomputed min/max structure.

The painter chooses between two paths each frame. If the visible changes number fewer than a quarter of the plot width, it draws every sample exactly: step corners at their real time, linear points at their samples. Otherwise it draws one min/max column per pixel. In both paths the painter's work is bounded by the pixels, apart from the cost of finding each column's minimum and maximum. The summary below removes that cost for long histories.

What other viewers do

Every major waveform viewer has an analog mode. The tools agree on the basics: a per-row toggle on a shared time axis, step and linear drawing, numbers taken from the existing radix, a taller row, and an automatic range.

Taken: Surfer's three automatic ranges and its rule that the translator supplies the number. The min/max column drawing of Surfer and PulseView. Taller rows that stay on the preset grid. Vivado's drag to resize. The sample marks of GTKWave and PulseView, shown automatically instead of as a separate style.

Left out for now: fixed min/max ranges and their off-scale policies, which exist mainly to compare rows with a shared scale. Y-zoom gestures. Questa's backstep. Several signals overlaid in one row. Threshold conversion back to logic. None of them is needed for the first version, and each can be added later without changing the rules above.

Implementation

The work fits in volna-core: one row setting, one numeric query on translators, one painter, one drag gesture and a derived summary that is built only if measurements call for it. volna binds the key and shows the menu sections. volna-egui only has to build.

PieceIn volna-core
Row statechangedDisplayedSignal gains analog: Option<Analog { draw: Step | Linear, range: Trace | Window | Type }>. It is saved in the waves workspace entry, which moves to panel version 3.
NumbersnewTranslator::numeric_kind(), from which numeric(&ValueView) -> Option<f64> and limits(SignalShape) follow. Unsigned, hex and binary read the unsigned value, signed reads two's complement, and float and real read the float. Text, bit and enum translators return None, which hides the Draw section. The ValueView borrow keeps the paint path free of allocation.
Row heightsexistsThe RowHeight presets and prefix layout. Toggling analog on moves 1× to 3× and remembers the old height.
Height dragnewDrag::RowHeight in WaveModel::pointer, for every row kind. It snaps to the presets and applies to the selection.
Painternewpaint_analog_row in wave/paint.rs: an exact path below width/4 visible changes, otherwise first/min/max/last per column. It adds X/Z spans in the value colours, range labels, the zero line and sample dots, and it is covered by headless Scene tests.
RangesnewWhole trace, visible window and type limits. The window range eases in WaveModel::tick, like the viewport animation.
SummarynewMinimum, maximum and undefined per block of 64 changes, with a binary tree above the blocks, keyed by signal and numeric kind. It is built by LoadRequest::Summary on the load worker when a history of at least 16,384 changes first turns analog, shared through the Document, counted by the memory meter and released with its plot. At about 0.75 B per change it is far smaller than a full f64 copy. It serves the whole-trace range, window ranges and dense columns in O(log n); a zoomed-out frame at 10⁷ changes went from 580 ms to 1.1 ms.
Cursor and hoverchangedThe overlay draws the cursor dot, and the hover readout reports a sample or a column's minimum and maximum. Edge navigation and snapping are unchanged.
CommandsnewAction::ToggleAnalog (bound to a), plus MenuAction::Draw and MenuAction::Range as sections of the existing format menu.

Nothing changes in VTR or in the client–server protocol. Analog drawing is presentation: the row settings live in the workspace, and every number is derived in the client from the immutable histories that local and remote sessions already deliver. A VDB profile could later suggest analog rows, as docs/VDB_APPNOTE.md already anticipates with its “analog rendering hints”.

Plan

  1. Numbers and state. Add Translator::numeric and limits, the row setting, ToggleAnalog, the menu sections and the workspace field, with headless model tests.
  2. Painter. Implement the exact and per-column paths, X/Z spans, labels and the cursor dot, with scene tests. These include a glitch that must survive every zoom level.
  3. Measure. Time paint per frame at full zoom-out on a procedural 10⁷-change signal (analog_cost) and compare against the same view drawn digitally. Direct scans cost 58 ms per 10⁶ changes, far over 4 ms, so the block summary was built. Both results are in docs/RATIONALE.md. The C910 CoreMark buses are still to be measured.
  4. Ranges and gestures. Add the window range with its easing, the height drag for all rows and the hover readout.

Open questions

  • Should real signals open as plots by default, or should that be a setting in settings.json?
  • Is 3× the right height for a new analog row? Surfer uses 4× and Vivado about 4.5 rows.
  • When a vector shown as Hexadecimal plots as a sawtooth that wraps at zero, should the row suggest Signed?

Later

Possible follow-ups: fixed min/max ranges shared by selected rows, overlaying a reference signal in the same row, fixed-point scaling and units from VDB profiles, and a vertical zoom gesture.
