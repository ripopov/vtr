Proposal · Viewer theme

A theme for reading hardware.

Volna, the proposed default look of the viewer, is built on the Instrument design system. The chrome is grey and colour is kept for data. Every value stroke reaches 4.5:1 on the canvas, and every signal state keeps its meaning in greyscale.

Design language

Seven rules.

  1. Colour is data.Panels, bars, borders and text use the Instrument greys. Hue appears only where the trace puts it: values, states, stages and markers. The accent blue marks what you control: the cursor, the selection and keyboard focus.
  2. One hue, one meaning.Green is a driven value, red is unknown, amber is high impedance, orchid is don't-care and grey is weak. No state shares a colour with the cursor, as don't-care shares One Dark's blue today. Markers are labelled, so their colour is only a second cue.
  3. Equal weight, measured.Colours are specified in OKLCH, where equal lightness looks equally light. HSL's single 58% lightness gives today's stage ladder a violet at OKLCH lightness 0.55 and a yellow at 0.78, so the yellow stage draws the eye whatever it means.
  4. Every state has a shape.X is a hatched band, Z a line at mid level, don't-care a dotted line, weak a dashed one, and a flushed instruction is drawn hollow. Switch the demo to Grey: nothing is lost.
  5. Readable by everyone.About one man in twelve has a colour-vision deficiency. Neighbouring pipeline stages therefore alternate lightness as well as hue, and stay apart under simulated deuteranopia, protanopia and tritanopia.
  6. Quiet grid, loud signals.Contrast is a hierarchy: grid lines at 1.3–1.4:1, value strokes and text at 4.5:1 or more. The eye lands on the waveform first and on the scaffolding only when it looks for it.
  7. Light is first-class.Volna Light takes the same hues at print lightness rather than inverting the dark theme. Z turns from yellow to amber-brown, because yellow vanishes on white; Surfer's light theme moved Z to purple for the same reason.

Values

Every value has a colour and a shape.

A 1-bit signal is a line at the top or the bottom of its row, and a high value is filled at 10% so a long high reads as a block. A bus is a hexagon outline with its value inside in Lilex. Unknown values are the one thing an engineer must never miss, so X gets the strongest cue: a red line at mid level over a hatched, tinted band. Z stays a bare line at mid level, don't-care is dotted and weak drive is dashed.

Where a single pixel column holds two or more changes, the row becomes a dense band at 55% of the signal colour, so a busy clock never looks like a constant. Coalesced event arrows keep the signal hue but move far from it in lightness, brighter in Volna Dark and deeper in Volna Light, so they differ in brightness rather than hue.

Show

Waveform panel rendering

Draw what happened, at every zoom.

Colour says what kind a value is; geometry says when it happened and how. These rules fix how every shape on the wave canvas is drawn, from one edge to a whole run squeezed into a thousand pixels, and what the panel shows under the pointer.

Rules View Zoom

Drag to pan. With the proposed rules, hover a row to find its nearest edge and, on a bus, every segment with the same value.volna/volna/examples/landing.vtr · 0–1685 ns

We read the renderers of Surfer, GTKWave, PulseView and vaporview. All four sample each pixel column and keep only its last state, so an X that starts and ends inside one column disappears when you zoom out; PulseView's source says its merged edges become ambiguous. None of them highlights every occurrence of a value. Dinotrace, GTKWave and Surfer draw an all-zero bus as a low line, which Volna adopts. The rules below borrow what they do well: PulseView's per-block change summaries for skipping quiet stretches, Surfer's 6px edge snap and event clusters with counts, Tracy's count on folded zones, and Perfetto's min, max and last value per pixel with the range printed on the track.

  1. Geometry is time.Every edge sits on its change's pixel column, and on a bus the crossing point, not the slant, marks the change. Level lines and edges are 1px, snapped to the device pixel grid and drawn without anti-aliasing; only slants and analog lines are smoothed.
  2. The pixel column is the unit.The painter already asks each history for the last change at every column's right edge, so a frame costs columns × log(changes) whether the trace holds ten changes or ten million. Every rule below is a rule about one column, and none adds work per transition.
  3. Nothing hides under aliasing.A column with two or more changes shows everything it holds. If every value in it is unknown, it is the hatched X band. If X or Z is mixed with real values, it keeps its activity fill and gets 1px rails in the X or Z colour, so neither the unknowns nor the traffic around them disappear. Today such a column is one green band. The per-block summary gains a few bits recording which value kinds occur, so the rule stays within the column budget.
  4. Activity has a strength.An aliased column's opacity follows its change count on a log scale, from 34% for two changes to 75% for sixty-four or more. A burst, a slow toggle and a quiet stretch then look different in the whole-run view, where today every aliased column is the same 55%.
  5. Clocks show periods, not noise.Once a declared clock's half period drops under 3px, it becomes a band labelled with its frequency and period. A gated stretch is a dashed low line marked “gated”, and a frequency change starts a new label. At closer zoom it is a square wave without the high fill, whose stripes would only add noise. Today a fast clock aliases into the same band as a busy bus.
  6. Buses keep an honest outline.Hexagons get 4px slants (3px today) on each side of the crossing, and the label starts 4px after the slant. Labels already stick to the left edge of the panel when a segment starts off screen, and segments narrower than 5px already join the aliased band; that band now follows rules 3 and 4.
  7. Numbers keep their last digits.When a hex or decimal value does not fit, it keeps its least significant digits behind a leading ellipsis, …0210 rather than 8000…, because neighbouring addresses and counters differ at the end. Text and enum values keep their beginning. A label shorter than two characters is dropped rather than shown as a lone ellipsis.
  8. States get a tint.Enum and text rows, such as FSM states and phases, fill each segment with a stable tint derived from its value, so a recurring state is recognisable before its label is readable. Numbers stay outlines. The tint takes one of six hues that stay clear of the X red and the Z amber, at 22%, too faint to compete with a state colour.
  9. Z and partial X keep their shape on buses.A high-impedance bus is a line at mid level, as a single bit is; today it is an amber hexagon. A bus with only some bits unknown keeps its signal outline and shows the unknown digits in the X colour; only a fully unknown value gets the hatched band.
  10. Zero reads as idle.A bus holding all zeros is drawn as a low line that the neighbouring slants run into, without a label, as Dinotrace, GTKWave and Surfer do. An idle counter, an empty queue or a cleared data bus then looks like a low signal, and every nonzero value stands out as a hexagon. The value is still one hover away.
  11. Analog rows show their scale.The row prints its maximum and minimum in its corner in faint Lilex. Aliased columns keep today's min–max envelope over the 10% area fill, so a one-sample spike survives any zoom.
  12. The pointer finds edges.Hovering a row marks its nearest change within 6px with a 2px accent line and its time in the header,, and a click puts the cursor on that edge. On a bus row, every segment holding the hovered value lights up, so repeats and a state's return are found without a search.
  13. Events count themselves; scaffolding recedes.A coalesced event arrow carries a ×n count when there is room. Rows stay 24px without zebra stripes; groups are divided by a 1px border; the time grid is drawn only at labelled ticks, and a clock ruler adds a cycle grid once a cycle is 8px wide.
  1. Row: 24px on the 4px grid.
  2. Inset: 5px above and below a 14px trace.
  3. Level line: 1px, snapped; a high value adds a 10% fill.
  4. Edge: 1px, on the change's pixel column.
  5. X: a mid-level line over a 12% tint, hatched at 45° every 5px.
  6. Change time: the crossing point of a bus.
  7. Slant: 4px on each side of the crossing.
  8. Label: Lilex 12px, 4px after the slant, kept at the panel's left edge.

Pipeline

Stages alternate lightness, not only hue.

Hue still follows pipeline order, from blue at fetch to red at retire, as Konata and today's Volna do. Each stage is one OKLCH step along that arc, and neighbouring stages alternate between two lightness levels, so a hue shift that one reader cannot see still shows as a light and dark pair. The stage name inside each cell has at least 6.4:1 against its fill in both themes.

Flushed instructions keep their cells but lose their fill: an outline with hatching says “fetched, never retired” in any colour vision. Stalls on other lanes stay a neutral band under the cells, and an instruction still in flight ends in a dashed edge.

Deuteranopia simulated with Machado et al. 2009 at full severity.

Hierarchy browser

Find any signal in a 200,000-signal design.

Every session starts in the sidebar. It should show where a design's signals are, which parts are moving right now, and get any signal onto the waves in a few keystrokes. The demo is the openC910 core running CoreMark: 6,958 scopes and 204,905 variables, straight from the benchmark trace.

Rules Try

Type in the search field or pick a search above. Arrows and Tab move through the panes; double-click, Enter or drag adds a variable to Waves; with the proposed rules, clicking a wave row reveals it.c910_coremark.vtr · 25,000–25,100 ns · variables of x_ct_ifu_top

We read the browsers of Surfer, GTKWave and vaporview, and the manuals of Questa, Vivado and SimVision. All of them put a scope tree over a signal list. Only the commercial ones show each signal's value at the cursor. None of the open-source filters ranks its results or shows what matched: Surfer's fuzzy mode keeps only a yes or no and sorts by name, GTKWave takes a regular expression, and vaporview matches substrings level by level. No viewer shows how big or how busy a scope is, and none keeps a scope's ancestors in view while you scroll deep inside it. The rules below borrow VS Code's leaf-first fuzzy scoring and sticky scroll, nucleo's bonuses for matches at word boundaries, Zed's sticky rows and indent guides for GPUI lists, Questa's cursor value column, and GTKWave's drag, which keeps the drop target visible.

  1. Two panes, one search.Scopes stay above the variables of the selected scope, as in every viewer we read; putting variables inside the tree, as Surfer's tree mode does, would bury C910's 6,958 scopes under 204,905 rows. One field searches both. The tree narrows to the branches that hold matches, each scope counts its matches, and the lower pane lists the matches inside the selected scope, so picking a scope refines the search. Today the filter covers one scope unless search-everywhere is switched on, and then shows a flat list.
  2. Results are ranked, and show why.Every word of the query must match. A word found whole in the variable's own name ranks first, then one found whole elsewhere in its path, then letters scattered over word starts, so ib also finds x_ct_ifu_ibuf. The characters that matched are drawn in the accent colour. Today the filter is a case-insensitive substring of the name, listed in file order and cut at 5,000.
  3. One signal, one result.67% of C910's variables are ports that alias a signal recorded elsewhere; ifu_idu_ib_inst0_data alone has five paths. A result row stands for a signal: it is shown at its shortest best-matching path with a +n for the others. A scope's own list still shows every port.
  4. Scopes show size and activity.Each scope row counts its variables and has a 26px meter for the share of its signals that change in the visible time range; a scope where nothing moves is drawn faint. In this window 16 of 5,596 vector FPU signals change, as CoreMark does no floating point, while a third of the fetch unit's signals do. The counts come with the hierarchy. The meters need "did this signal change in the window?" for every signal in the design, not only those on the canvas. The hierarchy activity design answers it exactly from a per-signal index of long silences: 1.5 ms for all C910 signals from 0.73% of the trace, with windows narrower than 102.4 ns finished from the trace in 6–16 ms.
  5. Numbered siblings fold into runs.2,754 of 6,958 scopes sit in runs of four or more numbered siblings, such as the 64 reorder buffer entries. A run is one row, x_ct_rtu_rob_entry 0–63, with the counts and meter of all its members; opened, it lists them in numeric order, entry2 before entry10, and so does every list. Folding single-child chains, as VS Code does for folders, was measured and dropped: only 8 C910 scopes have one child and no variables.
  6. Depth stays readable.C910 is 14 levels deep, and the fetch unit sits 9 levels down. Rows indent 12px with 1px guides. When the tree scrolls, the ancestors of the top row stay pinned at the top of the pane, nearest last, taking at most 40% of its height, as in VS Code and Zed.
  7. Variables show shape, width and value.A variable's icon is its own wave shape, a step for a bit and a hexagon for a bus. Its width and its value at the cursor sit in right-aligned Lilex columns, and the value keeps its last digits like a bus label. A value that does not change in the visible range is faint, so static configuration and live state separate at a glance. Variables already in the wave panel carry a 2px accent bar.
  8. Adding works both ways.Double-click, Enter or drag a variable into the wave panel, which shows an insertion line while you drag. A wave row reveals its variable: the path opens, the scope is selected and scrolled to the middle of the tree, and the variable is selected. Today the sidebar has neither drag nor reveal.
  9. Keyboard first.Arrows walk the tree, and Left goes to the parent; Tab moves between the panes and Enter adds. Typing anywhere in the sidebar goes to the search field, and Escape clears it and gives the tree back as it was.
  10. Quiet chrome.Rows are 24px, like the wave rows beside them. Names are Lilex 12px; counts and widths are faint Lilex 11px. Scope and variable icons use one neutral colour; the three tints stay for streams, generators and log sites, whose icons the hierarchy proposal set. Selection uses the viewer's selection colour, and only the focused pane shows it at full strength.

Surfaces and type

The canvas is the deepest surface.

In Volna Dark the wave and pipeline canvas is the darkest surface; the name and value columns sit one Instrument step above it, and menus one more. In Volna Light the canvas is white and the panels are the page grey. Surfaces are separated by 1px borders; only menus and popovers have a shadow. Selection is a blue tint of the accent and hover a 4% lift of the text colour, so both stay transparent over the waveform.

Type is the website's pair. IBM Plex Sans at 13px sets names and chrome; Lilex at 12px sets values, times, stage names and instruction labels, with tabular figures so columns of numbers align. Rows stay 24px on the 4px grid. The cursor is a 1px accent line with a filled time chip; markers are labelled chips in the marker lane with their line in the marker colour.

Theme sheet

Thirty tokens, two appearances.

The tokens live in docs/design-system/tokens/viewer.css, so the website and the viewer share one source. Once this proposal is approved, volna-core gains a Volna theme built from these values. appearance.theme then defaults to volna, which follows the system's light or dark setting, and volna-dark and volna-light pin one of them. One Dark and the bundled palettes stay selectable.

The colour changes need four small painter changes: the X hatch, the dotted and dashed lines, hollow flushed cells, and an OKLCH stage ladder with alternating lightness. The rendering rules above are the larger piece of work; the only data they add is a few bits per summary block recording which value kinds occur. A core test will check that the theme matches this sheet and meets the same contrast floors.
