Markers that measure, and a way back to every one of them

Most hardware debugging revolves around a few instants: the request that stalled, the beat that carried bad data, the interrupt that fired too late. An engineer marks them, measures between them in time and in clock cycles, returns to them for hours, and tells colleagues where they are. This proposal gives each of those verbs one key or one gesture in Volna. It draws every measurement on the time axis, in time and in counted cycles of every declared clock, and it puts the whole model in volna-core.

Proposal with an interactive demo, 27 September 2026, planned as nine commits. The demo and its guided steps below run on a small load path that the page generates on load. A core clock slows from 1 GHz to 500 MHz, and an AXI clock is gated during a DDR self-refresh, so elapsed time and cycles disagree in both domains. The page builds on declared clocks (timelines, rulers, cycle snapping), the shared time overlay of the pipeline panel, the command palette and workspaces. The mock follows the page theme, drawing with Volna's One Dark and GitHub Light palettes.

What users need
Place, name, find, move and remove markers without dialogs. See the time and the cycles between any two of them at a glance. Never lose a marker to a stray key.
What changes
A Markers lane and a Measure lane on every timed panel, one explicit reference, a dozen key bindings, direct manipulation of chips, a navigator in the palette, and undo. It needs no new trace data.
Where it lives
A marker module and a measure function in volna-core, a shared lane layout in wave::overlay, and one gesture handler for wave and pipeline panels. Frontends host only a text field and the palette.

The proposal in eight decisions

  1. Three things on the time axis, each with one job. The cursor is where you look, and it drives the value column. Markers are the instants you keep. The reference is where you measure from. Clicks never move markers, and navigation never moves the reference.
  2. One key per verb, and Shift undoes the verb. M marks the cursor and, pressed again, names the marker; ⇧M removes it. R measures from the cursor; ⇧R stops. This is the same pairing Volna already uses for G/⇧G.
  3. Measurements are drawn, not requested. Adjacent markers are joined by a labelled span. The reference and the cursor are joined by a live span in their own lane. Both give the time and the cycles of every ruler clock, so no one needs to know that a readout exists.
  4. Cycles are counted, not divided. The count is the number of recorded rising edges between the two instants, taken from the clock's timeline. It stays right across DVFS, gating and a clock that has not started yet. A fraction appears only when an end lies mid-cycle, and it is labelled as such.
  5. Direct manipulation of chips. Click a chip to go to its marker, drag it to move the marker with snapping, double-click it to rename, and Alt-click or middle-click it to measure from it. A right-click lists the same verbs with their keys.
  6. Every marker is one keystroke away. . and , step through markers in time order. Digits jump to markers 1–9, and ' finds any marker by name. ` goes back to where the last jump started.
  7. Nothing is lost. Every marker edit is one undoable step, and there is no clear-all key. Numbers are small and stay the same for a marker's life, and markers and the reference are saved in the workspace.
  8. Crowding degrades in a fixed order. When space runs out, a label shortens, then the chip shows only its number, then neighbouring chips merge into a cluster that zooms in on click. Every marker stays visible at every zoom.

What a marker is for in hardware debugging

A marker is not a feature for its own sake. It serves six jobs that come up in almost every debugging session. They are listed below with a typical moment and what each costs today. The design is judged by the steps and the thinking each job takes, not by the number of options.

Two needs cut across the jobs. The first is the vocabulary a team shares: “marker 4, req B, is 80 core cycles before marker 5” must mean the same thing to a colleague opening the workspace and to an agent reading it through MCP. The second is trust. A marker must never move, disappear or change its number unless the user asked for it.

Where Volna is today

Document keeps markers: Vec<Marker { id, time, label }>, sorted by time, in a history::Journaled field, so every marker edit is already an undoable step. It rejects a second marker at the same time (volna-core/src/document.rs). The shared overlay draws a line and a chip labelled M{id} for every visible marker, in both wave and pipeline panels (wave/overlay.rs). Workspaces save the list.

The GPUI frontend binds M to Add Marker and ⇧M to Clear Markers. Clicking a chip moves the cursor there, and Shift-clicking a chip removes it. The status bar shows the cursor minus the nearest marker, in time and in whole cycles of each ruler clock.

  • The label is never shown or edited. The field exists, but no gesture sets it.
  • The measurement origin moves on its own. “Nearest marker” changes as the cursor moves, so the same readout means different intervals from one second to the next.
  • One keystroke clears the session's work. ⇧M removes every marker. Undo brings them back, but the key sits next to M.
  • Numbers only grow. After a day of adding and removing, markers are numbered in the 40s, which no key can reach.
  • No marker navigation, no dragging, no list.
  • The wave and pipeline models each handle chip clicks (wave/model.rs, pipeline/model.rs), with the same code twice.

What the survey shows

Adopted

  • Cursor plus a separate reference. Most commercial viewers pair the cursor with a second point: Verdi's marker on the middle button, GTKWave's baseline, SimVision's baseline, Vivado's secondary cursor and Visualizer's C2 1,13,14,16,17. VaporView puts its alt-marker on middle-click or Alt-click 7, which also works on trackpads; we take both. Wireshark's time reference and Perfetto's temporary span note are the same idea outside hardware 20,22.
  • The Δ must be drawn where the eye already is. GTKWave issue #6 asks how to measure between two markers (“cannot believe that there is no such function”), and VaporView #200 asks for a Δ that was already in the status bar 3,8. Surfer #265 asks for exactly the span we draw: “a horizontal line spanning between the markers with time difference displayed as number above the line” 6.
  • Adjacent deltas without configuration. Questa labels the delta between adjacent cursors on the timeline 12, and Visualizer's wave marker diff lists consecutive differences 13.
  • Counting cycles on a real clock. The only native counter we found is SimVision's count_edges between cursor and baseline 17. Questa and Verdi users set a grid period or a time unit equal to the clock period 12,16, which fails whenever the period changes. Surfer #265 asks for edge counts between markers 6.
  • Digits jump to markers. Surfer's 0–9 and REAPER's 1–0 do this 4,21. Vim's `` and JetBrains' mnemonic bookmarks show how cheap “go back” and named places make exploration 23,24.
  • Names matter more than numbers. Surfer #168 calls renaming “critical … ‘start of transaction 0’, ‘first failing data return’” 5. REAPER and Resolve bind adding, naming and removing markers to one letter with modifiers 21,29.
  • A marker list with absolute, adjacent and relative columns becomes the navigator. Saleae's annotations panel lists markers with their measurements 10, and DVE's Markers dialog is reported to offer the three views.
  • Snapping, but predictable. Snap-dragging gives precision without a mode 27. Saleae's interaction poll shows users want snapping they can rely on 11, so snapping is limited to the selected clock and the row under the pointer, as Questa and Vivado do 12,14.

Avoided

  • “The nearest cursor moves” (Questa). A click moves whichever unlocked cursor is nearest 12, so placing a second cursor needs locking or a special mouse mode. Volna's click only ever moves the cursor.
  • Middle button only (Verdi, GTKWave). Laptops have no middle button, so Alt-click and R do the same thing.
  • Δ only in chrome (GTKWave's toolbar, VaporView's status bar, Volna today). Users of both tools filed issues asking for a Δ the tool already showed 3,8.
  • An N×N distance matrix (Surfer's marker window). It grows as the square of the marker count, and the question is almost always about one pair. The reference answers any pair in one key.
  • Placement modes (Saleae's arm-A1-then-click). Held modifiers do not cause mode errors 25.
  • Unmovable or dialog-only markers (GTKWave named markers), and deletion that cannot be undone. The Tracy manual even requires holding Ctrl to enable the delete button 30; undo makes that friction unnecessary.
  • Random names and colours (Perfetto flags, Tracy annotations). Over a long session they carry no meaning. Numbers are stable, and colours follow the number.
  • Relabelling the time axis at a zero point (PulseView, Saleae's “Set as t0”). Absolute times must stay comparable with simulator log timestamps. The relative reading gets its own lane, and Volna's per-panel cycle origin already renumbers cycles when someone wants that.
  • Locked markers and cursor linking (Questa, Aldec). A marker moves only when its chip is dragged, so there is nothing to lock.

The design

The figure below is painted by the same code as the demo. It shows load B, with the reference on marker 1 and the cursor just after the last read beat. Marker 3 was removed earlier, and the other markers kept their numbers.

The cursor, markers and the reference

The cursor keeps its meaning: it is where the value column reads, one per panel or shared through the existing cursor link. A left click or drag moves it, snapping to an edge of the selected clock or a change of the row under the pointer within six pixels.

Markers belong to the document and appear in every timed panel. Each has a number, a time and an optional name. The number is the lowest free positive integer when the marker is created, and it never changes while the marker exists. Removing marker 2 frees “2” for the next marker, so the digit keys keep reaching the markers people actually have. Colours follow the number through the theme's marker palette.

The reference is at most one point: a time, or a marker that it follows when that marker is dragged. R puts it at the cursor, and Alt-click or middle-click puts it at the pointer. Either way it attaches to a marker that sits exactly there. ⇧R clears it. When its marker is removed, the reference stays where the marker was. The reference is navigation state like the cursor, so it is saved in the workspace but not journaled for undo.

Only explicit gestures set it. Volna today measures from the nearest marker, which makes the readout change meaning as the cursor moves; that rule is removed. A new marker does not become the reference either, because then the second marker of a pair would silently move the origin.

Exact times and readable references

A marker at an exact time needs no dialog: type the time or cycle into the palette (Go to 186 ns, Go to Cycle 185, which the palette already offers), then press M. The other direction matters as much. Copy as text on a chip or a span puts a readable reference on the clipboard, such as lsu_ddr.vtr marker 4 “req B” at 186 ns (core_clk 185, axi_clk 73), for a bug report, a chat or an agent. This is the “readable trace, signal and time reference” that the README's agent feedback path asks for, and MCP's markers.list returns the same text.

Names

A second M, a double-click or F2 in the navigator opens a text field over the chip. The frontend hosts it over a rectangle the core reports, the way it already hosts the group-name editor. When the marker has no name and the selected row changes exactly at the marker, the field offers that change as the name (req_valid ↑, state=SREF), fully selected: ↵ keeps it and typing replaces it. That is a suggestion the user sees and accepts, not an automatic label. Names are trimmed and limited to 48 characters. An empty name returns the chip to its number.

Crowding

The Markers lane is laid out from left to right in one pass over the visible markers, which a binary search finds in the sorted list. Each chip first gets its number. Chips that would touch merge into a cluster (⋯3). Then each chip grows to its name if the gap to the next chip allows, or to a name truncated to at least three letters. Spans are drawn between consecutive chips, and also to the nearest marker beyond each edge of the view, so an interval that crosses the edge still shows. A span label takes the longest of four forms that fits. The self-test checks these rules on random marker sets and zooms: every visible marker is in exactly one chip, no two chips overlap, and every label fits its gap. The layout of 10 000 markers, with a view on a few hundred of them, takes … ms in this page.

Navigator

The command palette gains a marker mode, opened with ' or by typing @ in the palette. It lists markers in time order with number, name, time, the step from the previous marker, and the distance from the reference in time and in cycles of the selected clock. These are the absolute, adjacent and relative views in one table. Typing filters by name words or number. ↵ goes to the marker, ⇧↵ measures from it, F2 renames it and Del removes it. The same rows are what an MCP markers.list returns.

Panels, links and workspaces

Markers and the reference belong to the document, so every wave and pipeline panel shows the same lanes. A table panel can show markers as divider rows later, through a row source. Each panel measures to its own effective cursor, which is the shared cursor unless the panel is unlinked. The workspace stores markers: [{id, time, label}] and reference: {marker} | {time}, never the journal. Markers are user annotations, so they never enter VTR, VDB or the remote protocol, following the boundary in the README.

Cycles are counted, not divided

A clock's position at time t is the number of its recorded rising edges at or before t, plus the fraction of the running cycle. The fraction is 0 before the first edge and while the clock is stopped. The cycles between a and b are the difference of the two positions. When both ends lie on edges, or where the clock is stopped, this is a whole number: exactly the edges in (a, b]. Otherwise it has one decimal, and the tooltip says “from mid-cycle”.

This needs only ClockTimeline::cycle_at, which the reader already provides from a clock's stretches in a binary search. It replaces today's clock::cycles_between, which counts whole cycles only and has no answer before a clock's first edge.

Load B shows why division is wrong. It waited . During the wait the core clock dropped to 500 MHz at , and the AXI clock stopped for while the controller was in self-refresh. Dividing by the period at the start gives core and AXI cycles. Counting gives and .

The same count is shown in three places: on the spans, in each ruler's value cell and in the status bar. It is signed on the live span (the cursor may be before the reference). The tooltip adds 1/Δt, the frequency of an event with that period, which oscilloscopes and Questa offer and which helps with clocks that were never declared.

Architecture

The behaviour belongs to volna-core, following Volna's first intent: the marker model, the measurement arithmetic, the lane layout, the gestures and the commands, all with headless tests. GPUI hosts one text field and the palette's list. egui draws the lanes through the shared painter and keeps its minimal feature set. MCP maps its tools to the same commands and queries.

Undo needs no marker-specific mechanism. Every edit goes through the journaled list, and Document::take_edits hands the list from before the edits to the app-wide journal with a label that names the edit: Add marker 4, Rename marker 4, Move marker 4, Remove all markers. The reference sits outside the journaled field, like the cursor.

Rules that keep it maintainable

  • One writer. Only Document's journaled marker list changes markers, so the journal, the workspace dirty flag and repaint requests cannot miss an edit.
  • Layout is pure. marker_lane takes times, a viewport, widths and a text-measure callback and returns rectangles. The same result drives painting and hit testing. Tests run it without a GPU, as this page's self-test runs its twin.
  • No derived caches. The sorted list is the index. A view reads O(log n + k) markers per frame. A separate index is added only if profiling of the frame_times test shows a need.
  • Extension points are enums, not flags. A new measurement endpoint, such as a transaction's begin and end or a log record's time, is a new way to set the reference or the cursor, not a new object. A new lane item is a new Chip or SpanMark variant.
  • Agents use the same verbs. MCP's markers.add, markers.rename, markers.remove and measure call the core commands and measure(), so an agent's marker is undoable and saved like a user's.

Alternatives considered

  • Measure from the nearest marker (today). The readout changes meaning as the cursor moves. Replaced by the explicit reference.
  • Make each new marker the reference. Placing the second marker of a pair would move the origin away from the first. Rejected for the same reason.
  • Many cursors, as in Questa and Aldec. This needs a rule for which cursor a click moves, and that rule is Questa's most common complaint. One cursor, markers and one reference cover the same measurements.
  • Region markers (start/end pairs) as a second object. Two adjacent markers already bound a labelled span that can be zoomed to and measured. A region type would double the edit, list and persistence code for little gain.
  • An all-pairs distance matrix. It grows with the square of the marker count. The navigator's “from R” column and the reference answer any pair.
  • Monotonic numbers. These are today's rule, and after a long session no digit reaches any marker. Lowest-free numbering keeps numbers stable per marker and small.
  • User-picked colours. The name carries the meaning, and colour follows the number, so the same marker looks the same in every panel and theme. Can be added later as an optional field.
  • Relabelling the time axis at the reference. Absolute times must match simulator logs, so the relative reading gets its own lane.
  • Markers in VTR or VDB. Markers are annotations of one investigation, not facts of the run or of the design.
  • Dividing Δt by the clock period. This is wrong across DVFS and gating (see Measuring).
  • Auto-generated names. A name that appears without being asked for is noise. The editor's suggestion is visible and must be accepted.

Tests

volna-core (headless)

  • Measure. Cycle counts equal brute-force edge counting on random edge pairs of gated, DVFS and single-edge timelines; fractions stay within one cycle of the edge count; negative spans and the time before a clock's first edge are covered.
  • Undo. Every marker edit is driven in the model-based history test (tests/history.rs), which replays random edit sequences by undo and redo against snapshots.
  • Numbering. Lowest-free allocation, stability under moves and renames, and restore of numbers from workspaces.
  • Lane layout. Chips cover every visible marker exactly once and never overlap, labels fit their gaps, and clusters form and split at the expected zooms.
  • Gestures. Drag with snapping and Esc cancel, click versus drag threshold, Alt/middle reference, double-click rename, in both wave and pipeline panels.
  • Commands. Every key's verb, reveal panning only off screen, ` swapping, and the workspace round trip with the reference.

Frontends and this page

  • GPUI. Display-list tests of both lanes in both themes, the hosted editor opening over the chip, palette marker mode, and VOLNA_SCREENSHOTS diagnostics. The ignored frame_times test runs before and after the painter change.
  • egui. Its screenshot test keeps rendering lanes through the shared painter.
  • This page. node --test docs/tests/markers-ux.test.mjs launches headless Chrome. It checks the self-test, layout at desktop and phone widths, each guided step's resulting state, keyboard and pointer gestures (drag with snapping, rename, reference, undo, navigator), the copied text, WCAG contrast of chip and span text in both themes, and that marker lines are painted in their palette colours. Plan: nine commits

The design lands in nine commits, one feature each. Every commit builds, passes cargo test -p volna-core and volna/volna/check.sh, gives the user something that is useful on its own, and updates the tests and documentation it touches. No commit adds a feature flag, or code that only a later commit calls. Undo is already in place: marker edits go through the document's journaled list (history::Journaled, undo and redo), so each commit only names its new steps and drives them in volna-core/tests/history.rs. Each picture is painted by the demo's code with only the features of that commit and the ones before it.

Commit 1

Markers lane

Marker chips leave the time header for their own lane under the clock rulers, in wave and pipeline panels alike. A chip shows its number in its palette colour. Chips that would touch merge into a cluster (⋯4): hovering it lists its markers, and a click zooms to them. A click on a chip still moves the cursor there, and M, ⇧M and Shift-click keep today's meaning.

Core
wave::overlay::marker_lane(): a pure layout of number chips and clusters over the visible slice of the sorted list, whose rectangles drive both painting and hit testing. TimeColumn gains the lane rectangle, so wave and pipeline layouts reserve it the same way. marker::input::press with LaneHit::{Chip, Cluster} replaces the duplicate chip code in wave/model.rs and pipeline/model.rs. marker_chip_bounds and marker_chips are removed.
Frontends
The GPUI canvas takes its hit rectangles from the lane layout. egui paints the lane through the shared painter.
Undo
No new edits. Zooming to a cluster is navigation.
Tests
Lane layout: every visible marker is in exactly one chip, chips never overlap, and clusters form and split at the expected zooms. Chip and cluster clicks in both panel kinds. Display-list tests in both themes. A frame_times A/B run, since the painter changes.

Commit 2

Numbers that stay small

A new marker takes the lowest free number and keeps it while it exists. ⇧M removes the marker at the cursor instead of every marker, and Remove All Markers becomes a palette command. Shift-click on a chip stops removing it, because Shift-click extends the selection everywhere else.

Core
MarkerId(NonZeroU32) and marker::free_id. Document::{add_marker, remove_marker, remove_all_markers} take a marker number instead of a list index, and next_marker is removed. Action::ClearMarkers becomes RemoveMarkerAtCursor, plus a palette-only RemoveAllMarkers.
Workspace
No change: workspaces already store the numbers, and restore keeps them.
Undo
take_edits labels the steps Add marker 2, Remove marker 2 and Remove all markers. The model-based history test drives all three.
Tests
Lowest-free allocation, numbers that stay the same when other markers are removed, restore from a workspace, and ⇧M with no marker at the cursor.

Commit 3

Walk and jump

. and , move the cursor to the next or previous marker. 1–9 go to marker n. ` returns to the cursor and view from before the last jump, and pressed again it goes forward. The view pans only when the marker is outside the middle 90% of it, so the zoom is kept.

Core
NavState::reveal(t) and the one-slot back. The actions NextMarker, PrevMarker, GoToMarker(n) and Back, also exposed through Command::named.
Frontends
GPUI binds the bare keys in the Waves and Pipeline contexts, and only while no text field has focus.
Undo
None: these are navigation, which stays out of the journal.
Tests
Step order, including markers at equal times and no marker in that direction. A digit with no marker of that number. reveal pans only when the marker is off screen. ` swaps twice back to the start.

Commit 4

Names

M on an existing marker, or a double-click on its chip, opens a name field over the chip. When the selected row changes exactly at the marker, the field offers that change (req_valid ↑) fully selected: ↵ keeps it, typing replaces it, Esc cancels, and an empty name returns the chip to its number. Chips grow to their name where there is room, shorten it to at least three letters, and otherwise show the number. The tooltip always has the full name.

Core
The lane layout gains the label step. AddMarker becomes AddOrRenameMarker. The group-rename editor is generalized to TextEdit { target: Group(..) | Marker(id), rect, text, select_all }, answered by one Command::CommitText. Document::rename_marker trims names and limits them to 48 characters.
Frontends
GPUI hosts the field over the rectangle the core reports. egui shows names but offers no editing.
Undo
Rename marker 4 is one step. Workspaces already store label.
Tests
Label rules in the layout. Suggestions for bit and bus rows. Commit, cancel and an empty name. The rename step in the history test.

Commit 5

Counted cycles

Cycle counts are the clock's recorded rising edges between the two times, plus the fraction of a running cycle when an end lies mid-cycle. They also have an answer before a clock's first edge and while it is gated. The status bar's Δ uses them at once. It still measures from the nearest marker until commit 7 replaces that rule.

Core
measure::measure(clocks, from, to) -> Measurement with Cycles::{Whole, Fraction, Loading}, built on ClockTimeline::cycle_at. It replaces clock::cycles_between, which gives whole cycles only.
Undo
Not applicable.
Tests
Counts equal brute-force edge counting on random edge pairs of gated, DVFS and single-edge timelines. Fractions stay within one cycle of the edge count. Negative spans and times before the first edge are covered.

Commit 6

Adjacent spans

Neighbouring markers are joined on the lane by a labelled dimension line. Its label is the longest of four forms that fits: the time and every ruler clock, then the selected clock and the time, then the selected clock, then the time. Spans also reach the nearest marker beyond each edge of the view. Hover shows the full measurement with 1/Δt, and a double-click zooms to the span.

Core
MarkerLane.spans (SpanMark) labelled through measure(), and LaneHit::Span for hover and zoom.
Undo
None: zooming is navigation.
Tests
Every label fits its gap. Spans to markers off the view. Double-click zoom. A frame_times A/B run.

Commit 7

Reference and live span

R puts the reference at the cursor, and Alt-click or middle-click puts it at the pointer. Either way it attaches to a marker at that time, and ⇧R clears it. A Measure lane appears with the R tag and a signed live span to the cursor, labelled like the adjacent spans. The interval is tinted across the rows, and Z zooms to it. The status bar reads the reference to the cursor, and the nearest-marker rule is removed.

Core
Reference::{Time, Marker} in Document, next to the journaled list but outside it. measure_lane(). The actions SetReference, ClearReference and ZoomToMeasurement. Status.delta becomes Status.measure.
Workspace
shared.reference is added and workspace::VERSION goes from 3 to 4. Restore rejects a reference to a missing marker.
Undo
The reference is navigation state and is not journaled. Removing its marker leaves it at that time.
Tests
R, ⇧R, Alt-click and middle-click. Detaching when the marker is removed. The workspace round trip and rejection of a dangling reference. The Z margin. Measure-lane display lists in both themes.

Commit 8

Direct manipulation

Dragging a chip moves its marker, snapping to the selected clock's edges and to changes of the row under the pointer within six pixels. The old position shows dotted, and Esc cancels. Alt-click or middle-click on a chip measures from it. Right-click menus on chips, spans and the live span list the same verbs with their keys, including Copy as text. A double-click on the time header or an empty part of the lane adds a marker there.

Core
Drag::Marker next to Drag::Cursor. marker::input gains drag, release, cancel and the menus as data. Document::move_marker, which a reference attached to the marker follows. marker::text() gives the readable reference, for example lsu_ddr.vtr marker 4 “req B” at 186 ns (core_clk 185, axi_clk 73).
Undo
One Move marker 4 step per drag, not one per pointer move. A cancelled drag records nothing.
Tests
The click-versus-drag threshold, snapping and Esc in both panel kinds. Every menu verb. The copied text.

Commit 9

Navigator

', or @ in the command palette, opens the palette's marker mode. It lists markers in time order with number, name, time, the step from the previous marker and the distance from the reference. Typing filters by name words or number. ↵ goes to the marker, ⇧↵ measures from it, F2 renames it and Del removes it.

Core
marker::palette_rows(query), whose distances come from measure(), and a MarkerNavigator action.
Frontends
The GPUI palette gains the mode and a Markers… toolbar button.
Undo
Del is a Remove marker step. Everything else is navigation.
Tests
Filtering and order, the columns, and each key. Palette display lists in both themes.

After commit 9, MCP adds markers.* and measure over the same commands, once the MCP adapter lands.

Open questions

  • Count prefixes. Should a digit followed by . step that many markers (Vim-style)? This would conflict with digits as jumps, so it is left out until someone asks.
  • Edge counts of a selected signal. The live span could count the rising edges of the selected row, which answers “how many beats” (Saleae, SimVision). It fits Measurement as one more optional field; is it wanted in the first version?
  • Reloading a re-run. Document::reset_state clears markers when a trace is closed or replaced. When the same path is reopened after a re-run, markers could be kept, since their times usually still mean the same events. Should that be automatic, or offered once as “Keep 5 markers from the previous run”?
  • Markers from logs and searches. A “Mark all matches” command for searches and “Mark this record” for log rows would add markers through Document in one undoable step. Which comes first?

Glossary

Cursor
The instant a panel reads values at. It is moved by clicks, drags and keys, and shared between linked panels.
Marker
A kept instant with a number, a time and an optional name, shared by all panels of the trace.
Number
A marker's identity for keys and people: the lowest free positive integer at creation, unchanged while the marker lives.
Reference
The one point measurements start from: a time, or a marker it follows. Set with R, Alt-click or middle-click.
Adjacent span
The labelled interval between two neighbouring markers on the Markers lane.
Live span
The signed, labelled interval from the reference to the cursor on the Measure lane.
Selected clock
The ruler clock that clicks snap to and [/] step through; compact labels show its cycles.
Cluster
A chip standing for markers too close together to draw apart at the current zoom.
Journal
The inverses of marker edits, replayed by undo and redo; kept in memory only.
DVFS, gating
A clock changing speed, or stopping, during the run; both make time ÷ period wrong.
