Trace Driver: четыре способа ответить на вопрос «почему у этого сигнала сейчас такое значение?»

При отладке RTL часто нужно выяснить, почему сигнал принял определённое значение в заданный момент времени. Функция Trace Driver позволяет проследить, как сформировалось это значение: пройти по цепочке зависимостей назад во времени, через регистры и границы модулей, до внешних входов. В документе представлены четыре варианта интерфейса для такого анализа.

Проблема

  • При ручном поиске причины приходится постоянно переключаться между исходным кодом, временной диаграммой и иерархией проекта. Если цепочка проходит через несколько регистров и модулей, легко потерять ход рассуждений.
  • В коммерческих отладчиках (Verdi, SimVision, Questa) для этого предусмотрена трассировка источников сигнала (драйверов); в просмотрщиках с открытым исходным кодом такой возможности нет.
  • Связка VTR + VDB объединяет значения сигналов со сведениями о структуре и семантике проекта. Это позволяет просмотрщику объяснять происхождение значений.

Возможности функции

  • Дерево причин для пары «сигнал @ момент времени»: значения, типы зависимостей (данные, условие, выбор входа мультиплексора, тактовый фронт) и соответствующие операторы в исходном коде. Дерево также показывает, когда регистры сохраняли прежние значения и какие внешние входы повлияли на результат. Поиск идёт назад по тактам с явно заданным ограничением глубины.
  • Работа в привычных средствах отладки: исходный код со значениями сигналов в момент, указанный временным курсором; временная диаграмма с группами, маркерами и стрелками; палитра команд.
  • Задача этого документа — выбрать, как показать такое дерево в интерфейсе с неперекрывающимися панелями.

Все четыре варианта ниже — интерактивные макеты на одних и тех же данных: небольшой конвейер из двух регистров и мультиплексора, трасса top.q @ 26 пс из 27 узлов, значения, полученные при моделировании, тёмная тема просмотрщика. В макетах работают выбор узлов и строк, переходы по стрелкам и идентификаторам в коде, а также переключатели режимов.

Принципы проектирования интерфейса

Десять правил, общих для всех четырёх вариантов

  1. Узел задаётся сигналом и временем. Каждый узел представляет пару сигнал @ момент; можно указать состояние непосредственно перед событием (25⁻). Щелчок по узлу устанавливает временной курсор и открывает оператор, сформировавший значение, в контексте нужного экземпляра модуля.
  2. Каждому типу зависимости соответствует свой цвет. data — синий, control — янтарный, clock — серый, mux sel — фиолетовый. Цвета берутся из палитры выбранной темы и одинаково используются в дереве, графе, метках на временной диаграмме и подсветке идентификаторов в коде.
  3. Зависимости по тактовому сигналу скрыты по умолчанию. Их можно показать одним переключателем.
  4. Сквозные порты свёрнуты по умолчанию. Свёрнутая цепочка показана в виде u1.d → u0.q: связи между уровнями иерархии показаны в сокращённом виде. В примере это 12 узлов вместо 27.
  5. Результаты остаются в основном рабочем пространстве. Они отображаются в отдельной панели, в группе на временной диаграмме или во встроенном блоке рядом с исходным кодом, без плавающих окон.
  1. Сначала оператор, потом объявление. Переход ведёт к оператору присваивания, сформировавшему значение; место объявления сигнала получает дополнительную подсветку.
  2. Сохранение значения регистра и внешние входы отмечаются явно. Пояснение выводится рядом с узлом: «на фронте № 2 значение сохранилось, поскольку en = 0».
  3. История переходов всегда видна. Пройденный путь отображается в строке навигации; для перемещения по нему служат Alt+← / →. Временной курсор перемещается только по щелчку, но не при наведении указателя.
  4. Сигнал добавляется на диаграмму одним действием. Достаточно щелчка с зажатой клавишей Alt или нажатия a.
  5. Trace X — режим поиска источника неопределённого значения. Используется тот же механизм трассировки: поиск начинается со значения X и останавливается на первом узле со значением, отличным от X. В интерфейсе появляются красный маркер и сводка «первый источник X».
1
Вариант 1 · дерево причин

Панель Driver Trace: дерево причин с фильтрацией и столбцом операторов

Аналоги: SimVision Trace SignalsQuesta Active Driver Path Detailsсписок кандидатов Indagoметки входов D / C / I в Verdi

В отдельной панели дерево причин представлено таблицей: сигнал, значение, момент времени, тип зависимости и оператор, сформировавший значение. Все сведения видны сразу. События на тактовых фронтах и случаи сохранения значения регистра показаны отдельными строками с пояснениями. Щелчок по строке перемещает временной курсор и открывает соответствующий участок исходного кода. Кнопка + в конце строки или двойной щелчок добавляет сигнал на диаграмму с меткой типа зависимости.

Попробуйте: щёлкните по top.u0.q @ 25⁻ и посмотрите, как панель исходного кода переходит к строке 5 в экземпляре u0 с курсором на 25⁻; обратите внимание на расположенную ниже янтарную строку с пояснением о сохранении значения. Включите clocks, чтобы увидеть узлы тактовых событий, или fold ports, чтобы свернуть сквозные соединения. Нажмите + у top.en, чтобы добавить сигнал с меткой типа зависимости.

Интерактивный макет. Панель Waveform слева сверху, панель Source Code под ней, новая панель Driver Trace справа. В строке состояния указаны число видимых узлов и общее число узлов, а также перечислены первопричины — внешние входы, на которых заканчивается поиск.

Размещение результатаНовый тип панели DriverTrace; в рабочем пространстве открывается одна такая панель. Строка навигации хранит историю запросов (top.q @ 26 › top.en @ 15⁻). Выбор узла новым корнем добавляет запрос в историю, а Backspace возвращает к предыдущему запросу.
СтолбцыSignal — имя сигнала с отступом и значком раскрытия; имя свёрнутого узла зачёркнуто и показано рядом с именем оставшегося узла. Value — значение в цветах темы, X выделяется красным. @ time — момент времени с меткой pre для состояния перед событием. Reason — цветная метка типа зависимости. Statement — файл, номер строки и текст оператора. В конце строки — кнопка добавления сигнала.
Строки пояснений«⏱ PosEdge top.u0.clk @ 15, event #2» и «⏸ hold at 15: no active assignment» выводятся мелким курсивом под соответствующим узлом; их видимость задаётся кнопкой notes.
Связь с панелью исходного кодаПереход ведёт к активному оператору присваивания. Идентификатор в объявлении обводится рамкой, а в месте чтения значения выделяется зелёным фоном. На левом поле показаны метки ▶ (активное присваивание) и ↩ (место чтения). Экземпляр модуля определяется по иерархическому пути узла.
Клавиатура↑↓ перемещение, →← раскрыть/свернуть, ↵ сменить корень, a добавить, c тактовые зависимости, f свёртка портов, / фильтр по имени.
МасштабированиеОтрисовываются только видимые строки, а дочерние узлы загружаются по мере раскрытия дерева. Это позволяет работать с деревом из тысяч узлов, пока загружаются нижние уровни. При достижении предельной глубины появляется строка «… depth limit».

Сильные стороны

  • Прямое отображение результатов трассировки упрощает реализацию; для каждого диагностического сообщения предусмотрено место.
  • Подходит для глубоких деревьев; табличное представление упрощает фильтрацию и сворачивание ветвей.
  • Привычно пользователям SimVision и Questa; удобно проверять сравнением содержимого строк с эталоном.

Слабые стороны

  • Время указано числом в столбце; последовательность событий приходится восстанавливать мысленно.
  • Требует места: третья панель рядом с диаграммой и исходным кодом.
  • Сквозные цепочки и повторяющиеся листья top.clk без свёртки делают таблицу длинной.

Вариант 2 · граф во времени

Панель Temporal Flow: дерево зависимостей на оси времени

Аналоги: Verdi Temporal Flow ViewVisualizer Time Coneокраска Path Times в Questa

То же дерево представлено графом, в котором горизонтальное положение узла определяется временем. Столбцы соответствуют моментам трассировки и расположены в хронологическом порядке. Состояние перед событием («settled before 25») показано чуть левее самого фронта («posedge clk #3»). Комбинационные цепочки в пределах одного момента занимают дополнительные столбцы: например, связь sel, a → mux в момент 5⁻ читается слева направо. Цвет рёбер обозначает тип зависимости; на рёбрах данных размещены подписи операторов, а на узлах — пояснения о сохранении значения. На временной диаграмме под графом каждому столбцу соответствует маркер, который помогает сопоставить оба представления.

Попробуйте: наведите указатель на любой узел, чтобы увидеть пояснения к нему; щёлкните по u1.d → u0.q, чтобы установить временной курсор на 25⁻ и открыть участок кода, объясняющий сохранение значения; щёлкните по заголовку столбца, чтобы переместить временной курсор, сохранив выбранный узел. Выключите fit для масштаба 1:1 с горизонтальной прокруткой; включите clocks, чтобы увидеть рёбра тактовых зависимостей, идущие от столбцов с фронтами.

Интерактивный макет. Панель Temporal Flow сверху, панели Waveform и Source Code снизу. Пунктирные прямоугольники — внешние входы, пунктирные рёбра — зависимости по управлению или такту, сплошные синие рёбра обозначают зависимости по данным.

Размещение узловСтолбец определяется моментом времени, дополнительный столбец — глубиной комбинационной цепочки в этот момент. Узел занимает первую свободную строку, в которой ребро к родителю не пересекает другие узлы. Алгоритм детерминирован и не использует силовую модель размещения.
УзелИмя сигнала с указанием свёрнутого соединения, значение, метка input для внешних входов, пояснение ⏸ held @15 при сохранении значения. Тактовые узлы приглушены. Выбранный узел и соответствующая строка исходного кода подсвечиваются одинаковым цветом.
РёбраПричина → следствие, от потомка к родителю. Подпись оператора на первом ребре данных, входящем в регистр, показывает активное присваивание (else if (en) q <= d;) и позволяет перейти к нему щелчком мыши.
УправлениеЩелчок выбирает узел и перемещает временной курсор. Двойной щелчок или перетаскивание узла на диаграмму добавляет сигнал. Колесо мыши меняет масштаб; режим fit подбирает масштаб по размеру панели.
Несколько запросовПри трассировке второго сигнала в той же панели общие узлы объединяются, если совпадают сигнал и момент времени. Такой подход используется в Verdi; пользователи отмечали, что он помогает увидеть общую картину.
Сложность реализацииНовая панель с собственной отрисовкой текстовых блоков и рёбер в виде кубических кривых Безье, а также определением объекта под указателем. Сложность размещения — O(число узлов · число столбцов).

Сильные стороны

  • Расположение узлов показывает последовательность событий; сразу видны случаи сохранения значения и цепочки, охватывающие несколько тактов.
  • Маркеры связывают граф с временной диаграммой внизу; щелчок по заголовку столбца устанавливает курсор на соответствующий момент.
  • Привычен пользователям Verdi; наиболее наглядно демонстрирует возможности трассировки.

Слабые стороны

  • Для просмотра широких деревьев, охватывающих много тактов, нужны масштабирование и прокрутка; в режиме fit текст становится мелким.
  • Самый сложный в реализации вариант: требуется точно определять размеры текста и объекты под указателем.
  • Равные промежутки между моментами скрывают реальные интервалы времени; ось показывает порядок событий, а не их длительность; это нужно явно обозначить.

Вариант 3 · пошаговый анализ

Активная трассировка в панели Source Code: пошаговый поиск причин

Аналоги: Verdi Active Trace + Active Annotationпатент Novas на встроенную панель «Why»переход к источнику сигнала двойным щелчком в Visualizerдерево поиска причин Indago

Поиск ведётся непосредственно в панели исходного кода. Выделяется строка активного присваивания, а невыполненная ветвь условия приглушается. Идентификаторы сигналов, повлиявших на значение, подчёркнуты цветом соответствующей зависимости; щелчок по ним продолжает поиск. Под выделенной строкой открывается компактная панель непосредственных причин с цифровыми клавишами для переходов. История переходов отображается в заголовке. На каждом шаге временная диаграмма дополняется сигналом, маркером времени и стрелкой от причины к следствию.

Попробуйте: всплывающая панель показывает четыре причины u1.q = 03 @ 26. Нажмите 2 или щёлкните по d, чтобы перейти к источнику данных; продолжайте нажимать ↵, чтобы пройти по зависимостям данных до регистра в u0 и прочитать пояснение о сохранении его значения, затем 3, чтобы перейти к управляющему входу en. Alt+← возвращает назад; элементы истории в заголовке позволяют вернуться к любому шагу. (Щёлкните по макету, чтобы он получил фокус клавиатуры.)

Интерактивный макет. Основная работа ведётся в панели исходного кода. На временной диаграмме справа постепенно выстраивается цепочка сигналов с метками типов зависимостей, маркерами и стрелками «причина → следствие».

ЗапускКоманда в контекстном меню идентификатора или Ctrl+D, когда на нём стоит текстовый курсор. Та же команда для строки диаграммы открывает исходный код на активном присваивании и показывает панель причин. Если временной курсор не установлен, появляется соответствующее сообщение.
Всплывающая панельВ каждой строке указаны цифровая клавиша, метка типа зависимости, сигнал, значение, момент времени и пояснение; внешние входы помечены input. Пояснения о сохранении значения выводятся в строке заголовка. Панель привязана к выделенной строке, прокручивается вместе с кодом и закрывается по Esc. Она остаётся внутри панели исходного кода.
Оформление исходного кодаИдентификаторы сигналов, повлиявших на результат, выделяются цветом типа зависимости и пунктирным подчёркиванием. Невыполненная ветвь if приглушается; значок ▶ на левом поле отмечает активное присваивание. Оформление определяется по пояснениям к узлу и его дочерним узлам.
ЦепочкаИстория переходов u1.q@26 ‹ u1.d@25⁻ ‹ … показана в заголовке панели. Цепочка сохраняется в состоянии панели как список ключей узлов. При восстановлении рабочего пространства запрос можно выполнить повторно и построить цепочку заново.
Связь с диаграммойГруппа «trace: top.q @ 26» содержит сигналы, просмотренные при обходе. Для связей используются стандартные стрелки аннотаций, для тактовых событий — стандартные маркеры с именами #1 #2 #3.
Сложность реализацииНаименьшая: нужны встроенная панель причин, подсветка кода и хранение истории переходов. Отдельный алгоритм размещения узлов и новый тип панели не требуются.

Сильные стороны

  • Код, значения и причины видны рядом — такое представление ценят пользователи Active Annotation.
  • Проще всего в реализации и освоении; опытные пользователи могут быстро перемещаться по цепочке с клавиатуры.
  • Для результатов не требуется отдельное место рядом с диаграммой.

Слабые стороны

  • Интерфейс предполагает обход в глубину. В широком дереве, где у одного оператора много входов, приходится многократно возвращаться к развилкам. Это вновь усложняет навигацию — проблему, для решения которой в Verdi появился TFV.
  • Всё дерево никогда не видно целиком; трудно сравнить две ветви.
  • Нужно тщательно продумать размещение панели причин при прокрутке кода, особенно у нижнего края окна и рядом с длинными строками.

Вариант 4 · связи на диаграмме

Зависимости в панели Waveform: группа сигналов со стрелками, маркерами и интервалами сохранения значения

Аналоги: Questa Wave (Path Details) с курсорами Traceперетаскивание вывода в nWave в Verdiстрелки аннотаций и группы на диаграмме

Результат трассировки отображается непосредственно на временной диаграмме. Под выбранным сигналом появляется группа «why top.q = 03 @ 26» со связанными сигналами в порядке обхода дерева причин. Глубина показана отступами, тип зависимости — меткой у каждой строки. Стрелки соединяют моменты причины и следствия на соответствующих строках. Тактовые фронты отмечены именованными маркерами, а интервалы сохранения значения — закрашенными полосами с пояснениями. Щелчок по строке или стрелке перемещает временной курсор и открывает нужный участок исходного кода внизу. Переключатели расположены в заголовке диаграммы; группу можно свернуть обычным способом.

Попробуйте: наведите указатель на стрелку, чтобы прочитать пояснение; щёлкните по стрелке из top.mux в top.u0.q, чтобы установить курсор на 5⁻ и открыть строку 5 в экземпляре u0; выключите arrows, чтобы оставить только сигналы без стрелок; выключите fold ports, чтобы показать каждое сквозное соединение отдельной строкой; clear trace сворачивает группу.

Интерактивный макет. Одна панель диаграммы с развёрнутой группой трассы и небольшая панель исходного кода под ней. Янтарная полоса на top.first — сохранение значения на фронте № 2; три янтарных маркера — тактовые события, рассмотренные при трассировке.

Модель данныхРезультат трассировки представлен обычной группой в дереве элементов. Она содержит сигналы с аннотацией trace (ключ узла и тип зависимости). По результатам трассировки строятся стрелки, маркеры и полосы; все они удаляются командой clear trace.
ПорядокСигналы расположены в порядке обхода дерева в глубину: причина ниже следствия. Сигнал, который встречается дважды (например, top.en в моменты 5⁻ и 15⁻), занимает одну строку с двумя стрелками. В дереве для него потребовались бы отдельные узлы.
СтрелкиКубическая кривая Безье соединяет точку (сигнал причины, момент причины) с точкой (сигнал следствия, момент следствия). Начало стрелки для состояния перед событием расположено чуть левее фронта. Цвет обозначает тип зависимости; подсказка содержит пояснение механизма трассировки: «top.en = 0 @ 15⁻ → top.u0.q (control: if false)».
Маркеры и полосыТактовые события становятся маркерами с именами posedge #1..#3; интервалы сохранения значения — полосами с пояснением причины.
Связь с исходным кодомКак в варианте 1: переход ведёт к активному присваиванию, объявление обведено рамкой, место чтения выделено фоном. На левом поле показаны метки ▶ / ↩.
Сложность реализацииСредняя: нужны построение группы в дереве элементов, привязка концов стрелок ко времени и переключатели в заголовке. Новый тип панели не требуется.

Сильные стороны

  • Результат показан на линейной шкале времени вместе с изменениями сигналов. Интервалы сохранения значения и считывание входов перед событием видны непосредственно на диаграмме.
  • Используются существующие панели и обычные сигналы в дереве элементов. Доступны все функции диаграммы: цвета, форматы значений, группы и сохранение состояния.
  • Сигналы появляются на диаграмме сразу при трассировке; добавлять их отдельно не нужно.

Слабые стороны

  • При большом числе связей стрелки загромождают диаграмму. Уже примерно после 20 строк нужны сворачивание ветвей и приглушение стрелок по мере удаления от выбранного узла.
  • Пояснения причин и расположение операторов доступны только во всплывающих подсказках: для их просмотра нужно навести указатель.
  • Строки упорядочены по причинным связям, а не по иерархии проекта. Это может быть непривычно пользователям, которые вручную задают порядок элементов.

Общие подходы

  • Трассировка начинается в момент, указанный временным курсором; каждый узел результата — пара «сигнал @ время».
  • Результаты представлены деревом или списком, которые можно дополнить графом. Щелчок по результату открывает и подсвечивает соответствующий участок кода; само дерево остаётся в отдельной панели.
  • Лучшие инструменты различают данные и управление и показывают только реально повлиявшие входы.
  • Время показывают наглядно: с помощью шкалы, курсоров начала и конца трассировки, цветового различения текущих и предшествующих событий.
  • Для поиска источника X используется тот же механизм трассировки с другим условием остановки.

На что жалуются пользователи

  • Окна трассировки закрывают диаграмму (Verdi Active Detection).
  • Трассировка в крупном проекте может на несколько минут заблокировать интерфейс.
  • Каждый шаг перемещает временной курсор, хочет того пользователь или нет (SimVision).
  • Переход ведёт к объявлению, а не к оператору, сформировавшему значение.
  • Тактовые зависимости и сквозные порты перегружают представление; после нескольких переходов легко потерять контекст.

Design proposal · September 2026

Trace Driver: four ways to answer “why does this signal have this value right now?”

The most frequent question in RTL debugging is not “where is this signal declared” but “where did this value come from at this moment”. Trace Driver answers it in one action: it shows the chain of causes from the selected value backwards in time, across registers and module boundaries, down to the external inputs. This document proposes four interface designs for such a feature.

The problem

  • Manual root-causing is the “three windows back and forth” loop: source, waveform, hierarchy. A few registers deep and across module boundaries, context is lost.
  • Commercial debuggers (Verdi, SimVision, Questa) cover this scenario with proprietary driver-tracing features; open-source viewers have nothing.
  • The key idea of the VTR + VDB pairing is to keep design semantics next to the values, so that a viewer can explain, not only display.

What the feature must provide

  • A cause tree for a “signal @ moment” pair: values, typed reasons (data, condition, mux, clock edge), the source statement, register holds, external inputs. The walk goes backwards across clock events with explicit depth limits.
  • Presence where the debugger lives: source code with cursor values inline, a waveform with groups, markers and arrows, and a command palette.
  • The purpose of this document is to choose how to present such a tree inside a tiling interface.

All four variants below are live mockups on the same data: a small pipeline of two registers and a mux, the 27-node trace of top.q @ 26 ps, values from a real simulation, and the viewer’s dark theme. Nodes, rows, arrows, tokens and toggles in the mockups are clickable.

Design principles

Ten rules shared by all four variants

  1. A node is a pair. Every result is signal @ moment; a moment can be pre-event (25⁻). Clicking a node moves the cursor to that moment and the source tile to the statement that produced the value, in the right instance context.
  2. Reason has a color. data blue, control amber, clock grey, mux sel violet, from the active theme palette. The same colors in the tree, the graph, waveform badges and source tokens.
  3. Clocks off by default, one switch away.
  4. Port pass-throughs folded by default. The folded name stays visible as u1.d → u0.q: hierarchy is compressed, never hidden. In the example that is 12 nodes instead of 27.
  5. Never leave the tiling model. No floating windows; the result is a tile, a group on the waveform, or an overlay inside the source tile.
  1. Statement first, declaration second. The primary jump target is the active assignment; the declaration is a secondary highlight.
  2. Holds and external inputs are visible verdicts, not footnotes: “held at posedge #2 because en = 0”.
  3. A visible trail. The walk so far is shown as breadcrumbs and navigable with Alt+← / →. Only an explicit click moves the cursor, never a hover.
  4. Adding to the waveform is one gesture. Alt-click or a.
  5. Trace X is a mode. Same engine, seed at an X, stop at the first non-X node; the UI only adds a red marker and a “first X source” summary.
1
Variant 1 · the record

Driver Trace tile: a filterable causality tree with a statement column

lineage: SimVision Trace SignalsQuesta Active Driver Path DetailsIndago candidate listVerdi D / C / I input marks

A new tile shows the engine’s tree directly, as a table you can read top to bottom: signal, value, moment, reason, and the statement that produced the value. Nothing is hidden behind hover. Engine notes (posedge events, holds) are rows too, so the tree explains itself. Clicking a row moves the cursor and the source tile; the + at the row end, or a double-click, adds the signal to the waveform with a reason badge.

Try it: click top.u0.q @ 25⁻ and watch the source tile jump to line 5 in instance u0 with the cursor at 25⁻; note the amber hold row below it. Turn clocks on to see the trigger nodes, or fold ports to compress pass-throughs. Press + on top.en to add it with its badge.

Live mockup. Waveform tile top-left, Source Code tile below it, the new Driver Trace tile on the right. The footer counts shown versus total nodes and lists root causes: the leaves that are external inputs.

Result surfaceNew tile kind DriverTrace, one per workspace; a breadcrumb bar keeps previous queries (top.q @ 26 › top.en @ 15⁻) so re-rooting on a node is a push, and Backspace pops.
ColumnsSignal (indented, chevron, folded name struck through with the folded-to name), Value (theme value colors, X in red), @ time with a pre tag, Reason as a colored chip, Statement (file:line and source text), add button.
Notes rows“⏱ PosEdge top.u0.clk @ 15, event #2” and “⏸ hold at 15: no active assignment” render as small italic rows under their node; toggled by notes.
Source tile couplingTarget line = active assignment; the declaration token gets an outline, the token that read this value gets a green fill; gutter marks ▶ (active assignment) and ↩ (read site). The instance context follows the node path.
Keyboard↑↓ move, →← expand/collapse, ↵ re-root, a add, c toggle clocks, f fold ports, / filter by name.
ScalingRows are virtualized; children load lazily by depth, so even a tree of thousands of nodes is usable while the lower levels are still loading. Truncation shows as a final “… depth limit” row.

Strengths

  • Direct rendering of the engine model: lowest implementation risk, every diagnostic has a place.
  • Scales to deep trees; filters and folding are trivial on a tree table.
  • Familiar to SimVision and Questa users; easy to test with snapshot rows.

Weaknesses

  • Time is a number in a column; the reader must rebuild the timeline in their head.
  • Needs screen space: a third tile next to the waveform and the source.
  • Pass-through chains and repeated top.clk leaves make the table long without folding.
2
Variant 2 · the picture

Temporal Flow tile: the tree laid out on a time axis

lineage: Verdi Temporal Flow ViewVisualizer Time ConeQuesta Path Times coloring

The same tree, drawn as a graph whose x position is the moment. Columns are the distinct moments in the trace, in time order; pre-event columns (“settled before 25”) sit just left of their edge column (“posedge clk #3”). Combinational chains inside one moment become sub-columns, so sel, a → mux reads left to right at 5⁻. Edges are colored by reason, statement pills sit on data edges, and hold verdicts are printed on the node. The waveform tile below shows one marker per column, so the graph and the waveform share a time scale in the reader’s eye.

Try it: hover any node for its notes; click u1.d → u0.q to move the cursor to 25⁻ and the source to the hold; click a column header to move the cursor without changing the selection. Turn fit off for 1:1 scale with horizontal scrolling; turn clocks on to see trigger edges enter from the posedge columns.

Live mockup. Temporal Flow tile on top, Waveform and Source Code tiles below. Dashed boxes are external inputs, dashed edges are control or clock dependencies, solid blue edges carry data.

Layout algorithmColumn = moment; sub-column = combinational depth within the moment; lane = first free row that keeps the edge to the parent clear of other nodes. Deterministic, no force layout.
NodeSignal (with folded name), value, an input tag for external inputs, a ⏸ held @15 verdict for holds. Clock nodes are dimmer. Selected node shares the highlight color of the source target line.
EdgesCause → effect, child to parent. A statement pill on the first data edge into a register shows the active assignment (else if (en) q <= d;) and jumps to it on click.
GesturesClick = select and move cursor; double-click = add to waveform; drag node onto the waveform tile = add; scroll = zoom; fit scales the whole graph into the tile.
Multi-queryTracing a second signal into the same tile merges shared nodes (same signal, same moment), the Verdi behaviour users praised for seeing a high-level picture.
CostA new tile with its own painter: text boxes, cubic edges, hit testing. Layout is O(nodes · columns).

Strengths

  • The only variant where “when” is spatial; holds and multi-cycle chains are obvious at a glance.
  • Shared time scale with the waveform tile below; column headers double as cursor targets.
  • Matches what Verdi users are trained to expect; strongest demo value.

Weaknesses

  • Wide trees over many cycles need zoom and pan; text becomes small in fit mode.
  • Highest implementation cost of the four; needs careful hit testing and text measuring.
  • Equal spacing between moments hides real time gaps; the ruler is ordinal, not linear, and must say so.
3
Variant 3 · the walk

Active trace inside the Source Code tile: step from cause to cause

lineage: Verdi Active Trace + Active AnnotationNovas “Why” overlay patentVisualizer double-click-to-driverIndago investigation tree

No new tile. The source tile you already look at becomes the trace surface. The active assignment is the target line; the untaken branch is dimmed; each identifier that contributed to the value is underlined in its reason color and clickable. A compact popover under the target line lists the immediate causes with number keys, and a trail of chips in the tile header records the walk so far. The waveform tile keeps pace: each step adds the signal, a marker at its moment and an arrow from cause to effect.

Try it: the popover shows the four causes of u1.q = 03 @ 26. Press 2 or click d to follow the data; keep pressing ↵ to follow data to the register in u0 and read its hold note, then 3 to walk into the en control input. Alt+← goes back; chips in the header jump anywhere on the trail. (Click the mockup once so it has keyboard focus.)

Live mockup. The source tile owns the interaction; the waveform tile on the right accumulates the trail with reason badges, markers and cause → effect arrows.

EntryRight-click a token or press Ctrl+D with the caret on it; from a waveform row the same command opens the source tile at the active assignment and shows the popover. Requires cursor set; otherwise the popover says so.
PopoverRows: number key, reason chip, signal, value, moment, reason text; external inputs say input. Hold verdicts appear in the title line. Anchored to the target line, scrolls with the code, dismissed with Esc; never a separate window.
Source decorationToken decoration: cause tokens get the reason color and a dotted underline; the untaken if branch is dimmed; ▶ in the gutter marks the active assignment, all computed from the node’s notes and children.
TrailChips u1.q@26 ‹ u1.d@25⁻ ‹ … in the tile header; the trail is the tile’s serialized state (list of node keys), so a restored workspace can re-run the query and rebuild it.
Waveform couplingA group “trace: top.q @ 26” collects the walked signals; arrows are ordinary annotation arrows; markers are ordinary markers named #1 #2 #3 for clock events.
CostSmallest: a popover, a decoration pass, and a state list. No layout engine, no tile kind.

Strengths

  • Explains in place: the user sees the code, the values and the causes together, which is what Active Annotation users switch on first.
  • Cheapest to build and to learn; keyboard-driven walking is fast for experts.
  • Nothing competes with the waveform for space.

Weaknesses

  • Depth-first by construction: a wide tree (many inputs to one statement) needs repeated back-tracking, exactly the “three windows back and forth” loop Verdi’s TFV was built to remove.
  • The whole tree is never visible; hard to compare two branches.
  • Popover geometry inside a scrolling code view needs care near the bottom edge and with long lines.
4
Variant 4 · the overlay

Causal overlay in the Waveform tile: the trace as a group with arrows, markers and hold spans

lineage: Questa Wave (Path Details) with Trace cursorsVerdi drag-pin-to-nWaveannotation arrows and groups on the waveform

The trace lives where the debugger already is. Under the queried signal a group “why top.q = 03 @ 26” lists the traced signals in causal order, indented by depth, each with a reason badge. Arrows run from the cause’s moment to the effect’s moment across rows; posedge events become named markers; a hold becomes a shaded span with its verdict written on it. Clicking a row or an arrow moves the cursor and the source tile below. Toggles live in the waveform header and the group collapses like any other.

Try it: hover an arrow for its sentence, click the arrow into top.u0.q from top.mux to land at 5⁻ on line 5 in u0; toggle arrows off to see the plain rows; turn fold ports off to see every pass-through as its own row; clear trace collapses the group.

Live mockup. One waveform tile with the trace group expanded and a small source tile below. The amber span on top.first is the hold at posedge #2; the three amber markers are the clock events the engine walked.

Data modelThe trace group is an ordinary item-tree group whose children are ordinary signal items with a trace annotation (node key, reason). Arrows, markers and spans are derived drawings owned by the trace, removed together by clear trace.
OrderingDepth-first causal order, cause under effect; a signal that appears twice (e.g. top.en at 5⁻ and 15⁻) is one row with two arrows, which is exactly what a waveform row can show and a tree cannot.
ArrowsCubic from (cause signal, cause moment) to (effect signal, effect moment); pre-event moments start a hair left of the edge. Colors by reason; tooltip is the engine’s sentence “top.en = 0 @ 15⁻ → top.u0.q (control: if false)”.
Markers and spansClock events become markers named posedge #1..#3; holds become spans labelled with the reason.
Source couplingSame as Variant 1: active assignment as target, declaration outlined, read site filled, gutter ▶ / ↩.
CostMedium: an item-tree group builder, arrow endpoints in time rather than screen space, header toggles. No new tile kind.

Strengths

  • The trace is drawn on the real time axis, with real transitions; holds and pre-event sampling become visible instead of textual.
  • Zero new tile kinds; the result is just signals in the item tree, so it works with every waveform feature (colors, formats, groups, saved state).
  • Adding to the waveform is not a step any more; the trace is the waveform.

Weaknesses

  • Arrows crowd quickly; beyond roughly 20 rows the overlay needs per-branch collapse and arrow fading by distance from the selection.
  • Reason text and statement locations live in tooltips, so the “why” sentence is one hover away instead of on screen.
  • The group’s row order is causal, not hierarchical, which can surprise users who sort the item tree by hand.

What the field converged on

  • The trace is anchored at the cursor time; a result is a “signal @ time” pair.
  • Results are a tree or list, optionally with a picture; source highlighting is the destination of a click, not the container of the result.
  • The best tools distinguish data from control and show only the inputs that actually mattered.
  • Time is drawn: a ruler, trace begin and end cursors, “now / earlier” coloring.
  • X hunting is the same trace with a different stop condition.

What users complain about

  • Trace windows covering the waveform (Verdi Active Detection).
  • Whole-design traces blocking the UI for minutes.
  • Every step moves the time cursor whether the user wants it or not (SimVision).
  • Jumping to the declaration instead of the statement that produced the value.
  • Noise from clocks and pass-through ports; lost context after a few hops.
