# Native verification

The C++20 SDK writes VTR 3.2 and source-bound VTI 3.0. Its package version is 4.0.
The maintained test suite checks the implementation in this repository, including
interoperability with the independent Rust implementation.

## Run the checks

From the repository root, with a C++20 compiler, CMake, Python, Rust, and the
zlib/LZ4/Zstandard development packages:

```sh
cmake -S vtr-cpp -B build/cpp -DCMAKE_BUILD_TYPE=Release
cmake --build build/cpp --parallel
ctest --test-dir build/cpp --output-on-failure
python3 benchmarks/build.py
python3 benchmarks/run.py
```

The suite currently contains 36 CTest checks. The updated
[benchmark report](../benchmarks/report.md) is generated by the full default
suite, including independent source-replay checks for every read and query.
[Benchmark methodology](../benchmarks/README.md) defines the workload, process,
CPU-affinity, memory, and timing boundaries. Those results cover the measured
synthetic workloads and do not establish general simulator scaling or latency.

## Coverage

| Area | Evidence |
| --- | --- |
| Public typed API | Source binding, borrowed and nested payloads, lifetimes, logs, clocks, relations, queries, and retained results |
| Datatypes and pages | Independent Python oracles, exact representations, field widths, malformed input, bounds, and complete consumption |
| Waveforms | Producer replay and independent Rust decoding across stored/LZ4/Zstandard, inline/threaded capture, and zero/two encoding workers |
| Rust/C++ records | Both writers and both readers across all codecs and execution/encoding settings; typed values, global IDs, children, clocks, relations, and retained schemas |
| Activity indexes | Both languages write and read exact source-bound sidecars; identity checks and exhaustive sampled windows |
| Transport | SPSC publication/wraparound, producer ownership, frontier ordering, overflow storage, spill, bounded handoff, and shutdown |
| Failure handling | Encoding failures, ID exhaustion, output ordering, lifecycle errors, incomplete evidence, and recovery |
| Packaging | External installed-header consumer through `find_package(vtr CONFIG REQUIRED)` in Release and Debug |
| Tutorials | Complete programs for transactions, reading, relationships, waveforms, parallel recording, and recovery |

Tests and assertions are the authoritative coverage; an API compile check alone
does not prove runtime behavior. Header and page validation does not replace the
full-file uniqueness, ownership, and locator checks in `Reader::validate`.

## Verilator

The [integration guide](../integrations/verilator/README.md) pins the simulator
fork and gives build/smoke commands. Tests exercise output and aliases against
FST, the typed SystemVerilog/DPI adapter, inline/threaded callbacks, logging, and
VDB extraction. The generated log fixtures cover normal output, `$error`, fatal
exit callbacks, `$finish`, binary output, runtime diagnostics, and repeated dumps.
The native SDK has no process crash guard; Rust guard behavior is tested separately
in isolated Linux subprocesses.

## Additional configurations

CI runs the native suite in Release and in Debug with address/undefined-behavior
sanitizers, and tests the installed package and Rust workspace independently.
To run the sanitizer configuration locally:

```sh
cmake -S vtr-cpp -B build/cpp-sanitize -DCMAKE_BUILD_TYPE=Debug -DVTR_SANITIZE=ON
cmake --build build/cpp-sanitize --parallel
ASAN_OPTIONS=detect_leaks=1 UBSAN_OPTIONS=halt_on_error=1 \
  ctest --test-dir build/cpp-sanitize --output-on-failure
```

LeakSanitizer requires a process environment without a ptrace-based tracer.
Alternative-compiler runs need their own build directories and actual results;
the default Release result does not imply those configurations passed.
Keep all regressions in benchmark comparisons, investigate their cause, and record
the evidence for accepted tradeoffs with the relevant implementation change.
